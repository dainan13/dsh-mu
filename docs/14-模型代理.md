# 14 · 模型代理（key 只存在网关，实例里只有占位符）

## 为什么

原来每个实例的 `.credentials.yaml` 里放着**真 key**（`DSHMU_PLAN_*`），而插件、模型跑的
shell 都能读它。做完这一层以后：

- 实例里 `DSHMU_PLAN_*` = **`mu-relay`**（占位符）
- 真 key 只存在宿主的 `relay.json`（位于 `/etc/dsh-mu/gateway/`，`0640 root:nginx`），**不挂进任何实例 jail**
- 顺带解决：`docs/11` 里那条"套餐 key 对可见用户可读"的已知限制**不再成立**

## 拓扑

```
实例(DSH) ──HTTP──▶ 127.0.0.1:8099/mu-llm/<实例token>/<route>/<供应商路径>
                        │  网关 Lua（relay.lua）查 relay.json
                        │  覆写 Authorization / x-api-key，清掉占位符
                        ▼
                   https://<供应商>/<路径>        ← 真 key 只在这一跳
```

- 只监听 **loopback**（`relay_listen`，默认 8099），公网 `:80` 上没有这个入口
- 路径里的**实例 token**（32 hex，存在 `state.json`）保证 A 用户不能拿 B 用户的套餐额度
- 解析不到 token/route 一律 **403**，所以它不可能被当成开放代理

## 配置

| 键 | 默认 | 说明 |
|---|---|---|
| `RELAY_ENABLED` | `true` | 关掉就回到直连（真 key 写回实例），作为逃生开关 |
| `RELAY_LISTEN` | `8099` | loopback 端口 |

```sh
dsh-muctl config relay_enabled false   # 逃生：切回直连
dsh-muctl sync && dsh-muctl instance restart alice
```

## 已知副作用（P1 引入）

| 现象 | 原因 | 处理 |
|---|---|---|
| 对话里「网页搜索」报 `HTTP 401 … api key: ****elay is invalid` | 搜索工具直接调 DeepSeek 官方接口、读 `DEEPSEEK_API_KEY`，而 relay 模式下这个值是占位符 `mu-relay` | 需要联网搜索时，把**平台 DeepSeek key** 单独给该实例：`dsh-muctl instance api-key alice --key-file …`（注意：这会把真 key 写进该实例，破坏"实例无 key"的性质，按需开启） |
| 「运行命令」报 `spawn bash ENOENT`、搜索报 `ripgrep provider failure` | **已修复（0.9.2）**：根因是 jail 自建的 `/dev` tmpfs 缺少 runner 需要的设备视图，见下节 | 实例内可正常执行 shell 与 ripgrep 搜索 |

### 命令工具（`spawn bash ENOENT` / `ripgrep provider failure`）已修复

**根因不是 DSH，也不是 bash/PATH/capability/bwrap** —— 是 jail 里**自建的 `/dev` tmpfs**。
DSH 的 subprocess runner 需要完整的设备视图（`/dev/pts`、`/dev/fd` 等），
tmpfs 里只 `mknod` 了 null/zero/random 等几个节点，于是 runner 起不来，
而错误被统一包装成 `SubprocessExecutableNotFoundError` → 界面显示 `spawn bash ENOENT`（**有误导性**）。

定位方式（每一步都是实跑）：先用 `LocalSubprocessRuntime`（Proxy 伪造 ctx）做最小复现，
得到"网关 rootfs 成功 / 实例 jail 失败"的对照；再逐项加回 jail 的特性二分：

| 追加条件 | 结果 |
|---|---|
| 实例 rootfs + bind 运行时（普通 chroot） | 成功 |
| `+ unshare -m` | 成功 |
| `+ --no-new-privs` | 成功 |
| `+ 实例精确能力集` | 成功 |
| `+ 新 procfs`、`+ /proc/sys` 只读 bind | 成功 |
| `+ 运行时 ro`（也试过 rw） | 都失败 → 排除 |
| `+ self-bind`（`DSHMU_SELF_BIND` 开关） | 失败 → 排除 |
| `+ 加入 dsh-mu/<name> cgroup` | 成功 → 排除 |
| **`+ 私有 /dev tmpfs`** | **失败 ← 根因** |
| **改成宿主 `/dev` 只读 bind** | **成功 ✓** |

**修法**（`jail/dsh-mu-jail`）：`/dev` 从"私有 tmpfs + 手工 mknod"改为**只读 bind 宿主 `/dev`**。
只读 bind 保留了真正需要的安全性质——实例无法 unlink/替换宿主设备节点——同时所有节点可解析。

### jail 侧为 bwrap 修好的四件事（都已在机器上验证）

1. **capability**：`instance_keep_caps` 默认 `sys_admin,setuid,setgid` → `CapEff=00000000002000c0` ✓
2. **`/` 是挂载点**：rootfs 自 bind，且**必须在任何其它挂载之前**（放后面会把 `/proc`、运行时全盖住，反而破坏隔离）✓
3. **sysctl**：只读 bind 宿主 `/proc/sys`（bwrap 要解析 `overflowuid`）✓
4. **运行时路径**：新增 `DSH_RUNTIME_IN_JAIL`，把运行时挂到规范路径 `/usr/local/lib/node_modules/@deepseek-ai/dsh`（否则 jail 里会造出假的 `/var/lib/dsh-mu`）✓

判据：`ISOLATION PASS=21 FAIL=0 SKIP=2`（两条 SKIP 是有意保留 capability 的必然结果）、`bwrap --dev-bind / / echo` → `BW-OK`、`HOSTDIR-HIDDEN`、`RT-OK`。

## 注意

- 上游对 **User-Agent 与请求头**有要求（opencode 会查会话头、Cloudflare 会认客户端指纹）：
  代理**不改**这些头，所以"直连能用"的客户端经代理仍然能用
- 流式靠 `proxy_buffering off` + `proxy_http_version 1.1` + `Connection ""` + `gzip off`
- 超时给到 3600s（推理模型很慢），请求体上限 512m（长上下文/图片）
- 升级/改套餐后：`dsh-muctl plan sync`（重写 relay.json 与 patch）→ 重启实例
