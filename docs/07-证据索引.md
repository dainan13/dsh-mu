## 2. 怎么自己把证据跑一遍

```sh
# 全部 13 层（约 15 分钟，含干净 Alpine 排练与 2 分钟 soak）
sh tests/regression.sh --user <用户> --password <口令> --instance <实例>

# 想快一点：跳过最后一层（chroot 排练）
sh tests/regression.sh --fast --user <用户> --password <口令>

# 单层（各自独立、可单独跑）
dsh-muctl doctor                       # 前置条件与记录一致性
node tests/selftest.mjs --user U --pass P
node tests/ui-lint.mjs .               # 只读、秒级
sh  tests/cli-contract.sh <实例>        # 只读
python3 tests/api-contract.py --instance <实例>
sh  tests/acceptance.sh <实例> U P
python3 tests/fresh-machine.py --skip-install --user U --password P
sh  tests/isolation.sh <实例>
python3 tests/failure-modes.py --user U --password P --instance <实例>
node tests/doc-lint.mjs .              # 只读、秒级
python3 tests/soak.py --minutes 8 --workers 6 --user U --password P
python3 tests/artifact-audit.py . --tarball dist/dsh-mu-<ts>.tgz
sh  tests/doctor-fix.sh                 # 会短暂弄坏四样东西并修好，收尾必须 0 FAIL/0 WARN
sh  tests/log-rotation.sh               # 真跑一次轮转，验证服务继续写日志
python3 tests/user-flows.py             # 建一个临时账号，跑完改密流程后删掉
sh  tests/run-uid.sh                    # 切到 auto 建临时实例，验证后删掉并恢复配置
python3 tests/state-lock.py             # state.json 并发锁；会持锁约 3 秒，别与其它写操作同时跑
python3 tests/admin-surface.py           # 以临时系统账号走一遍 /admin/，跑完还原配置并删号
python3 tests/user-panel.py              # 普通用户的 /me 面板与「启动实例」
python3 tests/port-move.py               # 端口迁移与三个守卫
python3 tests/restore-owner.py           # 恢复后实例卷的属主
python3 tests/restore-plan.py            # 恢复前体检：会覆盖哪些卷、归档是否过旧
python3 tests/log-bounds.py              # 日志接口的限幅与错误路径
python3 tests/config-bounds.py           # 平台配置的边界（含危险但合法的取值）
python3 tests/name-key-bounds.py         # 账号名与 API key 的校验边界
python3 tests/limit-values.py            # 限额取值（0=不限、负值拒绝、单位换算）
python3 tests/password-bounds.py         # 密码最小长度在各入口一致
python3 tests/provider-probe.py          # provider 连接测试的各种回答
python3 tests/login-limit.py            # 登录限速；会消耗按 IP 的失败预算，建议最后跑
python3 tests/drift-audit.py . --apk dist/dsh-mu-0.1.0-r0.apk   # 仓库/实机/包是否一致
sh  tests/fresh-rehearsal.sh --clean --apk dist/dsh-mu-0.1.0-r0.apk \
                             --apk2 dist/dsh-mu-0.1.1-r0.apk
```

各层把日志留在 `/tmp/regression-*.log`（`regression.sh` 汇总行会指出具体文件）。

## 3. 证据的边界（哪些**还没**被证明）

| 未证明的事 | 为什么 | 怎么补 |
|---|---|---|
| 真实 OpenRC 起服务（网关/后端/实例服务） | chroot 里没有 init，排练直接拉起守护进程代替 | 真机上 `dsh-muctl install` 后看 `rc-service` 状态；`tests/acceptance.sh` 会验证 |
| 真实 jail 实例跑 DSH 并调用模型 | chroot 内无法嵌套 mount/cgroup 命名空间 | **真机 `python3 tests/fresh-machine.py`（不带 `--skip-install`）——唯一受人工门控的一步** |
| 多机/高可用、HTTPS 终结、真实负载下的容量数字 | 超出本期范围（设计为单机多租户） | 见下方"后续可选工作" |
| 包签名分发的信任链 | 当前是未签名包（`--allow-untrusted`） | 把 abuild 公钥放进 `/etc/apk/keys` 或用正式密钥重签 |
| `--must-change` 只是**提示**，不阻止平台用户使用实例 | 设计如此（避免把用户锁在门外），改密入口在用户面板 | 若需要"阻塞式"强制改密，见下方选项 |
