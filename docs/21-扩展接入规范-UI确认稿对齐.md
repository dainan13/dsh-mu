## 1. 三种形态

| | **A · 托管内容（推荐，ssh 要迁到这个）** | **B · 自带外壳（过渡，可并存）** | **C · 无配置页** |
| --- | --- | --- | --- |
| manifest | `admin.ui.chrome: "host"` | `admin.ui.chrome: "standalone"` 或没有 `ui` | 没有 `admin` |
| 左轨入口 | ✅ 有（按 `nav.order` 排） | ❌ 无 | ❌ 无 |
| 标题 / tab / 面包屑 | **宿主渲染** | 扩展自己渲染 | — |
| iframe 高度 | 填满内容区，**内部**滚动 | 同理（旧的 60vh 弹层废弃） | — |
| 主题 | 令牌 + 实时切换（不重载） | 只给令牌，扩展自己吃 | — |
| 深链 | 每页一个 URL | 只到扩展根 | — |
| 入口 | 左轨「插件与扩展」组 | 扩展管理里的「打开原始页面」 | 表格里「无配置页」 |

一个扩展可以**同时**声明 `pages` 与 `standalone`：既有 tab，也保留「原始页面」——**迁移期就这么用**。

## 2. manifest 契约（完整，含 18 号已有的字段）

```json
{
  "name": "ssh",
  "version": "1.5.0",
  "summary": "SSH 资源代理",

  "requires": { "dsh-mu": ">=0.32", "jail-api": 1, "ext-ui": 1 },

  "service": { "port": 8790, "entry": "/opt/ext/p/broker.py", "health": "/health" },
  "net": { "egress": ["10.0.0.0/8"] },
  "cgroup": { "cpu": "1", "memory": "512M", "pids": 256 },

  "admin": {
    "tab": "SSH 资源",
    "url": "http://127.0.0.1:8790/admin",

    "ui": { "kit": 1, "chrome": "host" },
    "nav": { "label": "SSH 资源", "icon": "terminal", "order": 10 },
    "pages": [
      { "id": "resources", "label": "资源", "default": true },
      { "id": "access",    "label": "接入", "badge": "warn" },
      { "id": "audit",     "label": "审计" },
      { "id": "doctor",    "label": "自检" }
    ]
  }
}
```

| 字段 | 必需 | 说明 |
| --- | --- | --- |
| `requires.ext-ui` | A 形态必需 | 宿主据此判断要不要按 A 形态托管；缺省按 B 形态处理 |
| `admin.url` | ✅ | 服务器侧地址；**浏览器永远走 `/ext/<name>/`**，不直连这个地址 |
| `admin.ui.kit` | A 必需 | 套件版本；宿主只托管它支持的版本 |
| `admin.ui.chrome` | A 必需 | `host` = 宿主外壳；`standalone` = 自带外壳 |
| `admin.nav` | A 必需 | 左轨入口；`order` 越小越靠上（平台上最多显示 5 个，超出进「更多扩展」） |
| `admin.pages` | A 必需 | 至少 1 页；`id` 只允许 `[a-z0-9-]`；`default: true` 指定首屏 |
| `admin.tab` | 旧字段 | `nav.label` 缺省时回退到它 |

**向后兼容**：没有 `admin.ui` 的扩展按 B 形态处理（自带外壳、无左轨项），
「扩展管理」里显示「自带外壳」；**不报错、不隐藏**。

## 3. 宿主外壳的行为（扩展可以依赖）

- 左轨只有一个「插件与扩展」组：组内按 `nav.order` 排，组尾固定「扩展管理」（不参与排序）。
- 标题、副标题、tab 条、面包屑由宿主画；iframe 里**不要再出现第二个 header**。
- 深链 `/admin/ext/<name>/<page>[/<sub>]`；未知 page 回退到 `default` 页。
- 主题切换通过 `postMessage` 通知，**不重载** iframe。
- 内容区只有**一层**滚动条（外层页面不动，内层滚动）。
- 820px 宽下 tab 横向滚动、表格不撑破。

## 4. 宿主 ↔ 扩展 协议 v1

同源 `postMessage`；生产环境 `targetOrigin` 收窄到本页 origin，并校验 `e.origin` 与 `e.source`。

| 方向 | type | 载荷 | 语义 |
| --- | --- | --- | --- |
| ext → host | `dshmu:ready` | `{kit:1, title?}` | 可交互，宿主撤 loading（8 秒兜底） |
| ext → host | `dshmu:title` | `{title}` | 覆盖标题右侧副文案（如 "3 个资源"） |
| ext → host | `dshmu:nav` | `{pages:[…]}` | 运行期追加页面（只增，不改不删） |
| ext → host | `dshmu:route` | `{page, sub?}` | 扩展主动导航，宿主更新 URL |
| ext → host | `dshmu:badge` | `{page, badge:"warn"\|null}` | 某个 tab 的小圆点 |
| ext → host | `dshmu:dirty` | `{dirty:boolean}` | 有未保存修改时拦切换 |
| ext → host | `dshmu:toast` | `{kind:"ok"\|"warn"\|"err", title, body}` | 用宿主 toast（样式统一） |
| ext → host | `dshmu:error` | `{message, hint?}` | 页面级错误，宿主显示 error 条 |
| host → ext | `dshmu:init` | `{kit, theme, mode, ext:{name,version}, page, sub, user:{name}}` | 握手 + 首屏上下文 |
| host → ext | `dshmu:theme` | `{theme, mode}` | 主题切换 |
| host → ext | `dshmu:navigate` | `{page, sub}` | 宿主切 tab / 浏览器后退 |

时序：

```
host                                     ext(iframe)
 │  src=...?theme=dark&page=resources&kit=1   ← 首帧就带对主题
 │────────────────────────────────────────▶
 │──── dshmu:init {kit:1, theme, page, user} ─▶
 │◀─── dshmu:ready {kit:1} ──────────────────── 宿主撤 loading
 │◀─── dshmu:title {title:"4 个资源"} ──────────
 │──── dshmu:navigate {page:"audit"} ──────────▶
 │◀─── dshmu:route {page:"audit"} ─────────────
```

### 7.2.1 握手必须幂等（生产环境务必照做）

`dshmu:ready` 只允许在**一次页面加载里回一次** `dshmu:init`：

```js
if (m.type === 'dshmu:ready') {
  const first = !extReady;
  extReady = true; /* …撤 loading… */
  if (!first) return;          // ← 少了这一行就是死循环
  postToExt({ type: 'dshmu:init', … });
}
```

原因：扩展收到 `init` 会回 `ready`。宿主若"每收到 ready 就回 init"，两边会无限对打 ——
而 iframe 本身**不会重载**、外壳也**不会重建**，所以网络面板和常规排查都看不出异常，
唯一的现象是 iframe 里 DOM 突变刷屏、鼠标 hover 抖动、按钮点不上。

同理：`dshmu:navigate` 只在 page/sub 真的变化时才发；`iframe.src` 只在值变化时才赋值。

宿主对扩展的承诺：

- iframe 尺寸由宿主保证；扩展**不要**用 `height:100vh` 撑页面，也不要再嵌滚动容器。
- 主题、`kit`、当前页、当前用户（只给 `name`）都在 `init` 里给全。
- **令牌/凭据永远不进 iframe 的 JS**：网关剥掉 `dshmu_session`、注入 `X-DSH-MU-Ext-Token`，浏览器侧看不到。

## 5. 组件套件 `ext-kit.css` v1

- 路径：`/mu-static/ext-kit/1.css`（版本进 URL，`Cache-Control: immutable`）。
- 内容：令牌 + 13 个组件（按钮 / 输入 / 表格 / 徽章 / 空态 / 通知 / 弹窗 / tab…）。
- **只做加法**：v1 内只加类、不改已有类的行为；破坏性改动 → `2.css`，平台同时托管两个 minor。

扩展页面里**不允许**出现自己的颜色值、字体、圆角 —— 全部用套件类。

## 6. 状态与错误（5 种都由宿主画）

| 状态 | 触发 | 宿主表现 |
| --- | --- | --- |
| 加载 | 打开页面、`ready` 未到 | 骨架屏，8 秒超时 |
| 没在运行 | `status != running` | 「扩展没有在运行」+ 直接可点「启动」 |
| 超时 | 8 秒无 `ready` | 提示 + 重试，不永远转圈 |
| 版本不兼容 | `kit` 不被支持 | 说明支持的版本 + 「打开原始页面」 |
| 无权限 | 令牌交换失败 | 引导回登录 |

扩展自己**不要再画**这几类整页状态。

## 7. 安全边界（给改平台 / 写扩展的人）

- 浏览器只访问 `/ext/<name>/…`（同源、经网关代理）；扩展的 `127.0.0.1:port` 不暴露。
- 网关注入 `X-DSH-MU-Ext-Token`，并加 CSP 与 `frame-ancestors 'self'`。
- 配置页里**不出现令牌**；地址可以出现（管理员要看）。
- `postMessage` 生产环境必须校验来源，禁止 `'*'`。

## 7.3 线上模板（provider-packages）的链路约束

**两个数据源必须分清，混用就是 bug**（2026-11-10 真实事故）：

| 数据源 | 内容 | 正确入口 |
| --- | --- | --- |
| DSH 内置 provider 目录 | `dsh` 自带那 40+ 个 provider | `POST /api/provider-import`（**按 id**） |
| 线上模板 `provider-packages/` | 我们自己维护的 `mu-*` 模板 | 浏览器取 JSON → `POST /api/packages`（**按内容**） |

事故经过：页面把线上模板的 id 发给了 `/api/provider-import`，后端按"DSH 目录"去找，
返回 `mu-deepseek is not in the harness provider directory`；另一台机器则是安装半途失败、
网关没起来，表现为 `unknown endpoint`。两条都要一起修，缺一条还会复现。

### 硬性规则

1. **模板列表与模板内容由浏览器直接拉**（`<base>/index.json`、`<base>/<name>.json`），
   服务器只做回退；这样服务器不能出网（客户机常见）也能导入，内网镜像也能用。
2. **模板库地址必须可配置/可输入**（弹窗顶部输入框 + 配置项 `provider_template_base`），
   禁止写死在代码里。
3. **状态列必须来自真实接口**（`GET /api/packages`），禁止用前端的原型数组。
   "已导入"是事实，不是装饰；写死过一次，直接把用户骗了。
4. 模板 id 统一 `mu-` 前缀，和 DSH 内置目录的 id 区分（`mu-deepseek` vs 目录里的 `deepseek`）。
   已有客户装的是内置 id 时，改名不影响它们继续运行，只是不会再被"覆盖导入"。

### 安装期的另一个坑（同一天踩到）

`dsh-muctl install` 会按地区把 alpine 镜像改成清华源；清华在部分网络里返回 **403**，
于是模板建不出来（`jail template build failed: missing usr/bin/node`），安装**半途而废**，
网关没有创建 → 管理台实际连不到后端 → 一切接口都像"路由不存在"。
现在：显式配置的 `alpine_mirror` 优先，并在构建前探测可达性，不可达自动回退
阿里 → 中科大 → 官方。
