# 09 · 构建环境（在哪台机、装什么、怎么重装）

> 本文只讲**构建**：把源码变成 `dist/dsh-mu-<ver>-r0.apk`。
> 运行/验收环境见 `docs/08-验收流程.md`；装机见 `docs/05-安装部署.md`。

## 1. 结论先说

| 要做的事 | 需要什么 | 需要装软件吗 |
|---|---|---|
| 打 apk（默认，未签名） | `apk-tools >= 3` 里的 `apk mkpkg` | **不需要**，Alpine 3.2x 自带 |
| 打 apk（可选，签名） | `abuild` + `apk-tools` | 需要 `apk add abuild` |
| 跑源码里的检查脚本 | `sh`、`python3`、`node` | 视脚本而定（见 §5） |

默认路径**不联网、不需要签名密钥、不需要 abuild**，所以一台刚装好的 Alpine 3.2x 就能出包。

## 3. 从零重建构建环境（重装后照做）

```sh
# 1) 基础工具（Alpine 最小系统一般已有 busybox tar；这里补齐 xz 与 curl）
apk add --no-cache tar xz curl git

# 2) 确认 apk-tools 3 的 mkpkg 存在（这是唯一的硬要求）
apk --help 2>&1 | grep -q mkpkg && echo "mkpkg OK"

# 3) 取源码（现在只有工作区这份；发版后可改为 git clone）
#    cd /path/to/dsh_install

# 4) 出包
cd dsh-mu
sh packaging/make-apk.sh --version 0.1.0
# -> dist/dsh-mu-0.1.0-r0.apk
```

可选（只有需要"本机 `apk add` 不带 `--allow-untrusted`"或想产出带签名的包时）：

```sh
apk add --no-cache abuild
sh packaging/make-apk.sh --signed --version 0.1.0   # 自动 abuild-keygen（首次）
```

## 4. 包怎么验证（不需要安装）

```sh
A=dist/dsh-mu-0.1.0-r0.apk

apk verify "$A"                       # 未签名 -> "UNTRUSTED signature"（这是预期）
apk --allow-untrusted manifest "$A"   # 列出全部文件 + sha256（应为 42 项左右）
python3 tests/artifact-audit.py . --skip-build   # 交付物审计（承诺文件/禁止项/体积）
```

真正的**安装/升级/卸载**验证在实机排练里做（`tests/fresh-rehearsal.sh --apk ...`），
工作区这台机只负责出包，不装、不跑服务。

## 5. 为什么工作区"只出包"就够了

- apk 的内容是**平台文件**（CLI 库、jail runner、网关 Lua、管理页、文档、测试脚本），
  不含 jail 模板（约 140 MB 在目标机上生成），也不含 node/openresty 运行时；
- 安装后的行为由目标机决定，所以**构建机不需要 node/npm/openresty/python 依赖**，
  只有 `apk mkpkg` 必需；
- 少数检查脚本需要 `python3`/`node`（例如 `tests/artifact-audit.py`、`tests/doc-lint.mjs`），
  它们是**可选**的，出包本身不需要。

## 6. 产物与发布（现状）

| 产物 | 位置 | 说明 |
|---|---|---|
| `dsh-mu-<ver>-r0.apk` | `dist/` | 单文件、未签名；安装用 `apk add --allow-untrusted` |
| `dsh-mu-<ts>.tgz` | `dist/`（或工作区根） | 源码包；不含 `dist/`，不含任何密钥/状态 |

发布到 GitHub Release 时只挂 `.apk`（**不签名、不发布到 Alpine 仓库**）。
将来的 GitHub Actions 用同一命令（Alpine 容器 + `apk mkpkg`）即可，不需要签名密钥。

## 7. 已知限制

- 默认产物**未签名**：安装必须 `apk add --allow-untrusted`；`apk verify` 会报 `UNTRUSTED`
  （这是设计，不是故障）。
- 旧的 `--legacy-v2` 手写打包器已删除：apk-tools 3（Alpine 3.22+）会以
  `v2 package format error` 拒绝 v2 包，它不可能产出可安装的东西。
- 交叉架构（在 x86_64 上打 arm64 包）未支持：包是 `arch = noarch`，
  但 `apk mkpkg` 与宿主机无关，`--arch` 选项留给将来需要时再加。
