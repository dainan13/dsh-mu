# 13 · 插件市场（Discover tab）：正确启用方式与客户机升级步骤

## 13.1 一句话结论

插件页的「**发现**」页签不是 DSH 版本差异，是**我们平台的市场功能**（0.50.0 引入）。
它的正确开法是：

```
① dsh.profile.bundles 里加入 @deepseek-ai/dsh-experimental-plugin-market-bundle
   （官方 bundle，自带 cordis.patch.yml，挂 plugin-market + ui-plugin-market 两行）
② 平台的 profile patch 里**只用一行普通 patch** 预置索引：
       - id: plugin-market
         config:
           indexes:
             - "http://127.0.0.1:8099/mu-llm/<relay-token>/__market/index.json"
③ sync 生成 feed（网关 jail 里的 market.json）+ 把 tarball 复制到平台的 market 目录
④ 重启实例（patch 只在启动时读）
```

## 13.2 三个**不能做**（都实测踩过，代价是实例起不来）

| 不能做 | 现象 | 证据 |
|---|---|---|
| 写 `- insert:` 操作 + `disabled: !!js "…"` | 实例静默退出，端口不绑定 | `failed to parse overlay …` / 解析器不认 `!!js` |
| 把市场行**追加到旧 overlay**（`.dsh-mu-provider.yml`，那里已是 `[]`） | 一个文件两个 YAML 文档 | `YAMLException: end of the stream or a document separator is expected (5:1)` |
| 让坏块留在 patch 里（它被当成"用户条目"永久保留） | 每次重启都失败 | 只能按文本匹配剔除（0.96.0 起 `_is_bad_market_leftover()`） |

## 13.3 诊断顺序（下次先在试验机跑）

```sh
dsh-muctl --version                                  # 必须 >= 0.96.0
dsh-muctl sync 2>&1 | grep -c warning                # 期望 0
P=/var/lib/dsh-mu/instances/<n>/home/.dsh/profiles/web/cordis.patch.yml
grep -c '!!js\|insert:' $P                            # 期望 0
grep -n -A3 'id: plugin-market' $P | head              # 期望普通行 + indexes
python3 -c "import json;d=json.load(open('/var/lib/dsh-mu/instances/<n>/home/.dsh/profiles/web/package.json'));print(((d.get('dsh') or {}).get('profile') or {}).get('bundles'))"
                                                      # 期望含 dsh-experimental-plugin-market-bundle
dsh-muctl doctor 2>&1 | grep -i market                # 期望 PASS market feed
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:<port>/   # 期望 401
```

若端口是 `000`：`tail -25 /var/log/dsh-mu/<n>.err.log`，YAML/`!!js` 一类错误一定在那里。

## 13.4 客户机升级步骤（连接恢复后照这个走）

> 前提：客户机当前 **0.95.5**（9 实例可用、图片可用）。**不要**装 0.95.8–0.95.13（含坏块）。
> 目标版本：**>= 0.96.0**。

```sh
# 0) 备份（记录级，几秒）+ 记录现状
dsh-muctl backup --out /root/before-$TS.tgz
dsh-muctl --version; dsh-muctl doctor | tail -1

# 1) 升级 CLI（先不 install，避免重启网关/实例）
apk add --allow-untrusted --force-overwrite /root/dsh-mu-0.96.0-r0.apk

# 2) 自愈：把每个实例 patch 里的坏块清掉（0.96.0 的 sync 会做）
dsh-muctl sync 2>&1 | tee /tmp/sync.log | grep -cE warning      # 期望 0
for p in /var/lib/dsh-mu/instances/*/home/.dsh/profiles/web/cordis.patch.yml; do
  n=$(basename $(dirname $(dirname $(dirname $(dirname $p)))))
  printf '%-12s !!js=%s\n' "$n" "$(grep -c '!!js' $p)"
done                                                             # 每个都应为 0

# 3) 逐个重启（一次一个，每个确认 401 再下一个；这是我踩过的最大坑）
for n in <实例列表>; do
  dsh-muctl instance restart "$n"
  curl -s -o /dev/null -w "$n=%{http_code}\n" http://127.0.0.1:<port>/
  # 若 000 → 停手，tail err.log，不要继续下一个
done

# 4) 市场收尾
dsh-muctl doctor | grep -iE "market|^FAIL|doctor:"
# 期望：PASS market feed … served to N instances

# 5) 让用户 Ctrl-F5 → 插件页应出现「发现」页签，来源显示 dsh-mu 插件
```

## 13.5 回滚（任一步失败）

```sh
# patch 回到旧版（坏块已剔除，安全）
dsh-muctl sync
# CLI 回滚
apk add --allow-untrusted --force-overwrite /root/dsh-mu-0.95.5-r0.apk
# 实例仍起不来时：instance rebuild <n>（保留 home/workspace），不要删实例
```

## 13.6 遗留

- `@dsh-mu/dsh-ssh` 扩展：客户机 1.2.1 → `.61` 1.4.1，需要扩展方给可升级 apk（已反馈）。
- 扩展服务脚本需一次 `dsh-muctl install` 才会带 `after dsh-mu-gateway`（否则开机会停）。

## 附：三个网关整页（登录 / 启动中 / 启动失败）

| 页面 | 何时出现 | 行为 |
|---|---|---|
| `/login` | 未登录 ✓ | 表单登录 ✓ 成功后 302 回 `next` ✓ |
| 实例正在启动 | 已登录、实例没就绪 ✓ | **每 3 秒整页重试** ✓ 同时请求 `/instances/<name>/ensure`（限流 10 秒一次）✓ |
| **实例启动失败**（0.96.6 ✓） | `ensure` 请求本身失败 ✓（配置坏 / rootfs 缺 ✓） | **不自动重试** ✗ 显示原因 ✓ 提供「重试」「退出登录」✓ 提示管理员看 `instance logs --stderr` ✓ |
| 未分配实例 | 账号存在但没绑定实例 ✓ | 503 ✓ 提示管理员 `dsh-muctl instance create` ✓ |

**验证方式（已实测 ✓）**：`tools/verify-fail-page.sh` —— 建一个临时账号 ✓ 停掉它的实例 ✓
再停掉 admin 后端（使 `ensure` 请求失败）✓ 访问 `/` 拿到「实例启动失败」页 ✓
起回后端后访问 `/` 回到「实例正在启动」页 ✓ 最后自动清理 ✓。

「启动失败」页的判据只有一条：**自动拉起那个请求失败了** ✗。
它不覆盖“请求成功但进程随后静默退出” ✗ —— 那种情况仍然停在「正在启动」页 ✓ 需要看 `err.log` ✓。
