# 13 · 插件（先下载，再配策略：受保护 / 预装 / 推送）

## 一条规则

> **平台不代管"谁能装什么"。** 用户仍可在**自己实例的 DSH 界面**里装插件（
> `dsh-plugin-manager` 走 pnpm）✓；平台只负责"**把要分发的插件先下载好**"✓，
> 再决定它**删不掉 / 新实例预装 / 推给已有实例**✓。

> 0.19.0 之前这里有一份"管理员清单 + 越过清单要管理员密码"的机制 —— **已删除** ✓
> （用户本来就有自己的 DSH 界面，那道门是**安全剧场** ✗，见 `CHANGELOG` 0.19.0）✓。
> 0.25.0 又把"强制安装"拆成 **预装 / 推送** ✓，并把"批准"合并进"添加"✓。

## 添加 = 下载 + 解析

```sh
dsh-muctl plugin add @scope/pkg[@version]        # npm
dsh-muctl plugin add github:owner/repo[#ref]     # GitHub（codeload tarball）
dsh-muctl plugin add is-odd --proxy http://127.0.0.1:7890
```

- 下载到宿主 `/var/lib/dsh-mu/plugin-cache/` ✓，并从 tarball 的
  `package/package.json` 读出**真实包名与版本** ✓
  （所以 `github:Arrosam/dsh-better-workspace-file-manager` 会变成
  `dsh-better-workspace-file-manager 1.2.0` ✓，不再出现"规格/包名对不上"✗）；
- **一个包只占一行** ✓：再添加同名包 = **替换** ✓（旧 tarball 与 `<slug>.json` 一起删 ✓），
  接口会回 `replaced_version` ✓；
- 失败**不产生任何记录** ✓；报错带 `curl exit=N` ✓ + curl 原文 ✓ + 环境里的代理变量 ✓；
- scoped 包名按 `@scope/name` 解析 ✓（版本从**最后一个** `@` 切 ✓），请求时编码成
  `@scope%2Fname` ✓；
- 默认代理：`dsh-muctl config download_proxy http://host:port` ✓（页面填的优先 ✓）。

## 三个开关

| 开关 | 生效时机 | 效果 |
|---|---|---|
| **受保护** | 需要**重启实例** | `node_modules/<pkg>` 在 jail 内**只读绑定** ✓（内核 EROFS ✓）；`sync` 补回依赖与 `dsh.profile.bundles` ✓、清掉针对它的 `disabled: true` ✓。**删不掉、停不掉** ✓ |
| **预装** | **新建实例**时 | 只有创建实例才装 ✓；已有实例重启**不会**补装 ✓ |
| **推送** | `sync` + **每次重启** | 推给已有实例 ✓，并在此后每次启动补齐 ✓（用户删了也会回来 ✓） |

> 为什么拆开 ✓：只想"以后新实例都有"的人 ✓ 不该被迫给现存实例装 ✓；
> 而"必须全天候存在"的人 ✓ 需要重启也补齐 ✓ —— 这就是"推送"✓。

## 安装怎么落地

`plugin add` 的 tarball 存在宿主 ✓；安装时**拷进实例 home** 的
`~/.cache/dsh-mu-plugins/` ✓，再用 `file:` 装 ✓ —— 插件本体**不联网** ✓。
它自己的依赖仍走 npm 镜像 ✓（内网就配 `download_proxy` ✓ 或换 `npm_registry` ✓）。

```sh
dsh-muctl plugin preinstall @scope/pkg      # 之后新建的实例自动装
dsh-muctl plugin push       @scope/pkg      # 推给已有实例，并在重启时补齐
dsh-muctl sync                              # 立即应用（会顺带重启跑旧代码的 admin）
dsh-muctl instance restart <name>           # 受保护要重启才挂只读
```

## 命令一览

```sh
dsh-muctl plugin list                        # 包 / 版本 / 来源 / 三个标志
dsh-muctl plugin add <spec> [--proxy URL]
dsh-muctl plugin remove <包名> [--delete-asset]
dsh-muctl plugin protect|unprotect     <包名>
dsh-muctl plugin preinstall|unpreinstall <包名>
dsh-muctl plugin push|unpush           <包名>
dsh-muctl plugin check                       # 下载链路自检（registry / github）
dsh-muctl plugin cached                      # 已下载的包与缓存报表
```

## 接口

```
GET  /api/plugin-policy
     → { policy: {name: {spec, protected, preinstall, push}},
         assets: {spec: {name, version, file, sha256}},
         instances: {inst: [已装插件]},
         matrix: {pkg: [已装实例]},
         offline: bool }

POST /api/plugin-policy {action:"add", spec, proxy?}      # 下载 + 解析 + 入库
POST /api/plugin-policy {name, protected?|preinstall?|push?}
POST /api/plugin-policy {action:"remove", name, delete_asset?}
```

## 状态与审计

- `state.json`：`plugin_assets`（spec → 名称/版本/文件 ✓）与
  `plugin_policy`（**包名** → spec/protected/preinstall/push ✓）；
- 资产过滤 ✓：tarball 不存在的条目不会被当成"可配策略"✓；
- 旧数据兼容 ✓：`mandatory` 字段读时映射成 `预装 + 推送` ✓；
- 平台代装/代卸写审计 ✓（`plugin.install` / `plugin.uninstall` ✓）。

## 安全边界（必须知道）

- 插件在**用户自己的 jail** 里跑 ✓：看不到别人的实例 ✓、出网受**出网策略**约束 ✓；
- 它只拿得到本实例的**凭据占位符** ✓（`DSHMU_PLAN_*` / `DSHMU_SEARCH` ✓），
  真实 key 只在宿主 relay ✓；
- 受保护是**内核级**（只读绑定 ✓），且实例**没有 `CAP_SYS_ADMIN`** ✓ → 无法 `umount` ✓；
- 平台不保证用户自选包的安全性 ✓ —— 那是他自己的 jail ✓。
