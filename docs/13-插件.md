# 13 · 插件（用户在实例里自己装，平台只管"受保护 / 强制安装"）

## 一条规则

> **平台不代管"谁能装什么"。** 用户在**自己实例的 DSH 界面**里装插件（
> `dsh-plugin-manager` 走 pnpm）；平台只负责两件事：**受保护**（装了就删不掉）和
> **强制安装**（新实例自动装上）。

> 0.19.0 之前这里有一份"管理员清单 + 越过清单要管理员密码"的机制 —— **已删除** ✓。
> 原因：用户本来就有自己的 DSH 界面，可以完全绕过它，那道门是**安全剧场** ✗
> （见 `CHANGELOG` 0.19.0）。现在只保留**可见性**和两个**真正能执行**的策略 ✓。

## 装在哪、怎么生效

- 安装 = 实例内的 `dsh plugin --profile <p> add <pkg>@<ver>`（pnpm）
- 落点 = `~/.dsh/profiles/<p>/node_modules`（实例自己的 home，可写）
- 生效 = **重启实例**
- 平台**看得到**：`instance_plugins()` 直接读 profile 的 `package.json` ✓
  （后台「插件」页的「各实例已装插件」就来自它 ✓，来源列区分 `平台` / `自装` ✓）

## 两个策略（后台「插件」页，两个独立勾）

| 勾 | 效果 |
|---|---|
| **受保护** | jail 启动时把 `node_modules/<pkg>` 做**同路径只读绑定** ✓（`RO_PATHS` → 内核 EROFS ✓）；`sync` 会把依赖与 `dsh.profile.bundles` 补回 ✓、并清掉针对它的 `disabled: true` ✓。**删不掉、也停不掉** ✓ |
| **强制安装** | `sync` / 新实例创建时若没装就 best-effort 装上 ✓，失败只 WARN ✓ |

语义边界 ✓：

- 只对**已装**的实例生效（`protected` 不会替你装 ✓；要"每个实例都有"就勾**强制安装** ✓）
- 受保护需要**重启实例**才挂上只读 ✓；策略本身立即生效 ✓
- 受保护的包**已被删**时（保护还没挂上就卸载了）→ `sync` 打 WARNING 提示改用强制安装 ✓
- 用户的"卸载" = 改 `package.json` + pnpm 删 ✓：只读挂载让 pnpm 删不掉 ✓，
  `sync` 再把清单补回 ✓ → 重启后照常加载 ✓

## 命令

```sh
dsh-muctl plugin policy                        # 列出所有策略
dsh-muctl plugin protect   <pkg>               # 受保护（删不掉）
dsh-muctl plugin unprotect <pkg>
dsh-muctl plugin require   <pkg>               # 强制安装（新实例自动装）
dsh-muctl plugin unrequire <pkg>

dsh-muctl instance plugin list <name>                    # 某实例装了什么
dsh-muctl instance plugin add|remove <name> <pkg>[@ver]  # 管理员代装/代卸
```

## 接口

```
GET  /api/plugin-policy      策略 + 各实例已装（后台 token）
POST /api/plugin-policy      { pkg, protected?, mandatory?, note? }
```

原先的 `GET/POST /api/plugins`（清单）与 `GET/POST /api/me/plugins`（用户自助安装）
**已删除** ✓ —— 用户走实例内的 DSH 界面，平台不再提供安装入口 ✓。

## 记账与审计

- 策略存在 `state.json` 的 `plugin_policy`：`{pkg: {protected, mandatory}}` ✓
- `instances.<name>.plugins` 仍记录"谁、何时、哪个版本、来源" ✓（平台代装时写入 ✓；
  用户自装的只有 profile 里的真实状态 ✓）
- 审计：`plugin.install` / `plugin.uninstall`（平台代装/代卸时）✓

## 安全边界（必须知道）

- 插件在**用户自己的 jail** 里跑：看不到别人的实例 ✓、出网受**出网策略**约束 ✓
- 它**能读到本实例的凭据占位符**（`DSHMU_PLAN_*` / `DSHMU_SEARCH`）✓ ——
  真实 key 只在宿主 relay 里 ✓，插件拿到的是无用的占位符 ✓
- 受保护是**内核级**（只读绑定）✓，且实例**没有 `CAP_SYS_ADMIN`** ✓（0.19.0 起）→ 无法 `umount` ✓
- 平台**不保证**用户装的包是安全的：那是他自选的包，跑在他自己的 jail 里 ✓
