## 阶段 1（3–5 天）：A 扩展通过 gateway 提供服务

拆成三件事，缺一不可：

1. **路由注册契约**：扩展 manifest 增加 `routes: [{prefix, upstream(unix/http), auth(session|token|none), methods, strip_prefix}]`，
   网关渲染时生成 `location` 并注入 `X-DSH-MU-User`
2. **会话对接**：
   - 页面内调用：`auth_request` → admin `/api/auth/verify` → 注入用户头
   - 系统级 WebDAV：OS 客户端只有 Basic Auth → 需要「DAV 令牌」（长期、可撤销、限实例/工作区）
3. **文件访问**：manifest 增加 `mounts: [{source: instances/<name>/home, target: /workspace, mode: rw}]`，
   由 jail 按实例过滤绑定

验收（WebDAV 场景）：页面点「浏览文件」→ 给出地址+令牌 → Windows 映射网络驱动器 / macOS Finder / Linux gvfs 均可挂载，且只看得到自己的工作区。

## 阶段 3.5（A 之后）：认证与会话（原第 5 项，扩展为"外部登录系统对接"）

**为什么放在 A 之后**：A 要定"扩展如何对外暴露 HTTP 与服务"，
而外部登录（OIDC/LDAP）本质上也是"gateway 上的一条受保护路由 + 身份注入"，
两者的会话/令牌/注入机制应当共用一套，先做 A 能避免返工。

| 子项 | 内容 | 量 |
|---|---|---|
| 会话无状态化 | 签名 Cookie（`{u,r,e,x}` + HMAC），网关只验签名/过期/epoch → 网关重启不掉线 | 1 天 |
| 用户级 epoch | `users[name].session_epoch`：踢人 / 改密 / 改角色 / 禁用 → bump 即失效（≤2s） | 半天 |
| 外部身份（OIDC） | 平台作为 OIDC RP：`/auth/oidc/{provider}/start|callback`，映射到平台账号，可只读同步（不自动建号） | 2–3 天 |
| 外部身份（LDAP/AD） | bind 校验 + 组映射到角色 | 2 天 |
| 会话管理页 | 在线会话列表、单条撤销、全局登出 | 1 天 |

> 决策记录（2026-11-20）：原「会话持久化」单独做价值有限；与外部登录合并后，
> 一套会话模型同时服务"本地口令 / OIDC / LDAP"，因此推迟到 A 之后。

## 运行时交付方式：结论（2026-11-21 实测）

**结论：只发布 squashfs 一种镜像；EROFS 不采用。**

| 场景 | loop 直挂 | erofs file-backed | squashfuse | 解压目录 |
|---|---|---|---|---|
| 特权 CT（.61，有 loop） | ✓ 零解压 | ✓（但体积是 squashfs 的 2.5×） | ✓ | ✓ |
| 非特权 CT（测试64，无 loop，有 fuse） | ✗ EPERM | ✗ EPERM | **✓ 实测通过** | ✓ |
| 无 loop 无 fuse | ✗ | ✗ | ✗ | ✓ 兜底 |

实测数据（同一份 673 MB 运行时目录）：

```
squashfs zstd                106 MB
erofs zstd,level=9,128K      261 MB   （需自编 erofs-utils：Alpine 包未编 zstd）
erofs zstd+dedupe(1.8.2)     157 MB   （该版本镜像本内核 EINVAL，不可用）
```

关键事实：
- 非特权容器里 erofs 与 squashfs 的 `mount(2)` 都返回 EPERM（内核只允许 FS_USERNS_MOUNT 的
  文件系统），所以**换镜像格式不能解决 CT 安装问题**，只有 FUSE 可以；
- erofs 文件直挂（无 loop）确实可用（内核 BACKED_BY_FILE + ZIP_ZSTD），但体积劣势明显，
  且要求宿主 `modprobe erofs`、要求自编带 zstd 的 mkfs；
- 因此：**squashfs + 随包 squashfuse** 是唯一同时满足"体积最小 / 特权与非特权都能跑"的组合。

落地（1.9.201–1.9.202）：
```
runtime_materialize 策略：loop → fuse → extract（逐级降级并说明原因）
随包 /usr/local/lib/dsh-mu/vendor/squashfuse/{squashfuse,fusermount3,lib/*}（约 1.8 MB）
诊断：dsh-muctl runtime-mount-test [镜像]
doctor：「运行时挂载方式」
```

部署要求（写进客户文档）：
```
非特权容器（uid_map 非 1:1）必须给 /dev/fuse，否则只能走"解压成目录"（每次升级运行时都要解压）
   LXC：lxc.cgroup2.devices.allow: c 10:229 rwm + lxc.mount.entry: /dev/fuse dev/fuse none bind,create=file
   PVE：容器 → 选项 → 功能 → 勾选 FUSE
```
