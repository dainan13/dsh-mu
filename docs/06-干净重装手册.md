# 06 · 干净重装手册（从零到可用）

> 适用：新机器、或把一台"跑了很久、状态不可信"的机器重建。
> 本手册是 0.79.1 在真机上从零走通后回写的，**每一步都带验收**。

## 0. 先决条件

- Alpine（3.20+），root 权限，**能出网**（apk 镜像 + npm registry）。
- `dsh-mu-<ver>-r0.apk` 放在 `/root`。
- **不要**先手工建 `/etc/dsh-mu`、`/var/lib/dsh-mu`；`install` 会生成。

## 1. 安装包（只做一件事）

```sh
apk add --allow-untrusted /root/dsh-mu-0.79.1-r0.apk
```

> ⚠️ **`dsh-muctl init` 不是安装**。它只生成 `/etc/dsh-mu/{secret.key,state.json,dsh-mu.conf}`，
> 然后尝试重启网关——此时网关还没构建，于是打印
> `rc-service: service 'dsh-mu-gateway' does not exist`。**这是预期的**，
> 真正干活的是下面的 `install`。

## 2. 安装（一条命令做完大部分事）

```sh
dsh-muctl install
```

它会：装依赖 → 在 gateway 模板里 `npm install -g @deepseek-ai/dsh@<ver>` →
构建 jail 模板 → 渲染并启动网关 → 起 admin 后端 → 生成 `admin.token` →
建 default plan → 跑 doctor。**验收：以 `install complete` + `doctor: … 0 FAIL` 结束。**

## 3. 修 musl 上的 pty

```sh
dsh-muctl runtime fix-pty      # 否则实例里的终端会崩
```

## 4. 加管理员和用户

```sh
dsh-muctl user add admin --role admin --password '<口令>'
dsh-muctl user add bob   --password '<口令>'
dsh-muctl instance create bob --user bob --cpu "50000 100000" --mem 536870912 --pids 128
dsh-muctl sync
```

**验收**

```sh
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:<实例端口>/   # 期望 401
dsh-muctl doctor | tail -1                                             # 期望 0 FAIL
```

## 5. 恢复 provider / 套餐（可选，从旧机器迁移时）

旧机器上先导出：

```sh
tar czf /root/dshmu-assets.tgz -C / \
  etc/dsh-mu/{dsh-mu.conf,providers.json,state.json} \
  var/lib/dsh-mu/{providers,plans,market}
```

新机器上放回：

```sh
mkdir -p /tmp/assets && tar xzf /root/dshmu-assets.tgz -C /tmp/assets
cp -a /tmp/assets/var/lib/dsh-mu/providers/. /var/lib/dsh-mu/providers/
cp -a /tmp/assets/var/lib/dsh-mu/plans/.     /var/lib/dsh-mu/plans/
cp -a /tmp/assets/var/lib/dsh-mu/market/.    /var/lib/dsh-mu/market/
chmod 600 /var/lib/dsh-mu/plans/*.key /var/lib/dsh-mu/providers/*.json
dsh-muctl sync
```

> 套餐属于某个用户；恢复后要么把同名用户建出来，要么在后台把套餐改归属。

## 6. 干净的四大坑（都是真机上踩出来的）

### 坑 1 · `init` ≠ `install`

见 §1。`init` 生成的配置是半成品，必须再跑 `install`。

### 坑 2 · 实例 profile 必须有默认 bundles（**最隐蔽** ✗）

我们自己的插件要进 `dsh.profile.bundles`，但**不能只写我们的插件** ✗。
DSH 新建一个 `web` profile 时写的是：

```json
{
  "name": "dsh-profile-web",
  "private": true,
  "dependencies": {},
  "dsh": { "profile": { "bundles": ["@deepseek-ai/dsh-base", "@deepseek-ai/dsh-web-app"] } }
}
```

缺这两个 → web 没有可服务的内容 → **`dsh` 直接 exit 0，什么都不打印** ✗
→ 服务端进程秒退、端口永不监听、`doctor` 只说 "service is up but not bound yet" ✗。
（`dependencies` 留空即可：包从运行时的 `node_modules` 解析，不需要 pnpm。）

### 坑 3 · `--patch` 里的 config 键名会随版本变

历史实现往 `~/.dsh-mu-provider.yml` 写 `sandbox-policy.defaultMode` /
`permission.defaultPreset`。0.2.1-rc.5 已经改了 schema ✗ → 整个 overlay 非法 ✗
→ 实例启动即崩 ✗，错误只写在 `err.log`。

现在这两条**不再生成**：jail 已经导出 `DSH_PERMISSION_MODE=danger-full-access`。

### 坑 4 · 真相在 `err.log`，不在 `<实例>.log`

`<实例>.log` 只有 `starting mode=serve …` 这种壳的日志；
子进程的报错全在 **`/var/log/dsh-mu/<实例>.err.log`**。
排障顺序：

```sh
tail -30 /var/log/dsh-mu/<实例>.err.log
awk '/starting mode=/{buf=""} {buf=buf $0 "\n"} END{print buf}' /var/log/dsh-mu/<实例>.err.log
```

## 7. 验收清单（全绿才算装好）

```sh
dsh-muctl doctor                     # 0 FAIL
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:80/login   # 200
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:<port>/    # 401
ls /var/lib/dsh-mu/instances/<n>/home/.dsh/profiles/web/node_modules    # 有 @dsh-mu/*
```

最后：浏览器登录 → 发一条消息 → 有回复 ✓（这一步只能人做）。
