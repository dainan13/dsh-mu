# 06 · 干净重装手册（从零到可用）

> 适用：新机器、或把一台"跑了很久、状态不可信"的机器重建。
> 本手册是 0.79.1 在真机上从零走通后回写的，**每一步都带验收**。

## 0. 先决条件

- Alpine（3.20+），root 权限，**能出网**（apk 镜像 + npm registry）。
- `dsh-mu-<ver>-r0.apk` 放在 `/root`。
- **不要**先手工建 `/etc/dsh-mu`、`/var/lib/dsh-mu`；`install` 会生成。

## 1. 安装包（只做一件事）

```sh
apk add --allow-untrusted /root/dsh-mu-0.79.1-r0.apk
```

> ⚠️ **`dsh-muctl init` 不是安装**。它只生成 `/etc/dsh-mu/{secret.key,state.json,dsh-mu.conf}`，
> 然后尝试重启网关——此时网关还没构建，于是打印
> `rc-service: service 'dsh-mu-gateway' does not exist`。**这是预期的**，
> 真正干活的是下面的 `install`。

## 2. 安装（一条命令做完大部分事）

```sh
dsh-muctl install
```

它会：装依赖 → 在 gateway 模板里 `npm install -g @deepseek-ai/dsh@<ver>` →
构建 jail 模板 → 渲染并启动网关 → 起 admin 后端 → 生成 `admin.token` →
建 default plan → 跑 doctor。**验收：以 `install complete` + `doctor: … 0 FAIL` 结束。**

## 3. 修 musl 上的 pty

```sh
dsh-muctl runtime fix-pty      # 否则实例里的终端会崩
```

## 4. 加管理员和用户

```sh
dsh-muctl user add admin --role admin --password '<口令>'
dsh-muctl user add bob   --password '<口令>'
dsh-muctl instance create bob --user bob --cpu "50000 100000" --mem 536870912 --pids 128
dsh-muctl sync
```

**验收**

```sh
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:<实例端口>/   # 期望 401
dsh-muctl doctor | tail -1                                             # 期望 0 FAIL
```

## 5. 恢复 provider / 套餐（可选，从旧机器迁移时）

旧机器上先导出：

```sh
tar czf /root/dshmu-assets.tgz -C / \
  etc/dsh-mu/{dsh-mu.conf,providers.json,state.json} \
  var/lib/dsh-mu/{providers,plans,market}
```

新机器上放回：

```sh
mkdir -p /tmp/assets && tar xzf /root/dshmu-assets.tgz -C /tmp/assets
cp -a /tmp/assets/var/lib/dsh-mu/providers/. /var/lib/dsh-mu/providers/
cp -a /tmp/assets/var/lib/dsh-mu/plans/.     /var/lib/dsh-mu/plans/
cp -a /tmp/assets/var/lib/dsh-mu/market/.    /var/lib/dsh-mu/market/
chmod 600 /var/lib/dsh-mu/plans/*.key /var/lib/dsh-mu/providers/*.json
dsh-muctl sync
```

> 套餐属于某个用户；恢复后要么把同名用户建出来，要么在后台把套餐改归属。

## 6. 干净的四大坑（都是真机上踩出来的）

### 坑 1 · `init` ≠ `install`

见 §1。`init` 生成的配置是半成品，必须再跑 `install`。

### 坑 2 · 实例 profile 必须有默认 bundles（**最隐蔽** ✗）

我们自己的插件要进 `dsh.profile.bundles`，但**不能只写我们的插件** ✗。
DSH 新建一个 `web` profile 时写的是：

```json
{
  "name": "dsh-profile-web",
  "private": true,
  "dependencies": {},
  "dsh": { "profile": { "bundles": ["@deepseek-ai/dsh-base", "@deepseek-ai/dsh-web-app"] } }
}
```

缺这两个 → web 没有可服务的内容 → **`dsh` 直接 exit 0，什么都不打印** ✗
→ 服务端进程秒退、端口永不监听、`doctor` 只说 "service is up but not bound yet" ✗。
（`dependencies` 留空即可：包从运行时的 `node_modules` 解析，不需要 pnpm。）

### 坑 3 · `--patch` 里的 config 键名会随版本变

历史实现往 `~/.dsh-mu-provider.yml` 写 `sandbox-policy.defaultMode` /
`permission.defaultPreset`。0.2.1-rc.5 已经改了 schema ✗ → 整个 overlay 非法 ✗
→ 实例启动即崩 ✗，错误只写在 `err.log`。

现在这两条**不再生成**：jail 已经导出 `DSH_PERMISSION_MODE=danger-full-access`。

### 坑 4 · 真相在 `err.log`，不在 `<实例>.log`

`<实例>.log` 只有 `starting mode=serve …` 这种壳的日志；
子进程的报错全在 **`/var/log/dsh-mu/<实例>.err.log`**。
排障顺序：

```sh
tail -30 /var/log/dsh-mu/<实例>.err.log
awk '/starting mode=/{buf=""} {buf=buf $0 "\n"} END{print buf}' /var/log/dsh-mu/<实例>.err.log
```

## 6.5 排障：**重启之后** cgroup 检查全红

真实故障（客户机，0.28.1）：重启后 `doctor` 里

```
FAIL  cgroup v2 mounted      /sys/fs/cgroup            cgroup v2 required
FAIL  cgroup controllers     none
FAIL  cgroup delegation      (缺 /sys/fs/cgroup/dsh-mu)
FAIL  cgroup limits writable [Errno 2] /sys/fs/cgroup/dsh-mu
```

**病因**（0.88.0 修掉的三个）：

1. 开机脚本把 `mkdir /sys/fs/cgroup/dsh-mu` 放在"根目录可写"检查**之后** ✗ ——
   容器里根组经常还被 PID 1 占着，脚本于是**静默 exit 0**，树永远不建 ✗。
2. 脚本自己**不挂 cgroup2** ✗ —— 只在我们渲染服务时挂过一次，重启就丢 ✓。
3. 服务**没有声明**对 `localmount` 的依赖 ✗ —— 可能在 cgroup2 挂好之前就跑 ✓。

**现在的行为（0.88.0+）**

- 先尝试 `mount -t cgroup2 none /sys/fs/cgroup` ✓ 幂等 ✓
- **先建树**再谈 delegation ✓ —— 即使 limits 不可用，实例也能启动 ✓
- OpenRC 服务 `need localmount` ✓
- 每次开机往 `/var/log/dsh-mu/cgroup.log` 写一行**自证** ✓：

```
2026-11-02T07:31:02 start mount=cgroup2 controllers=[cpuset cpu io memory hugetlb pids …]
2026-11-02T07:31:02 done root=[cpu io memory pids] tree=[cpu io memory pids] limits=yes
```

失败时也留痕 ✓（`no-cgroup2 …` / `not-writable …` ✓）。

**修复一台已经在故障状态的机器**

```sh
dsh-muctl upgrade                        # 到 0.88.0 或更高
dsh-muctl install                        # 重渲染服务（带 localmount 依赖）
rc-service dsh-mu-cgroup restart         # 立刻建树，不必重启
dsh-muctl sync && dsh-muctl doctor       # cgroup 相关应全 PASS
tail -3 /var/log/dsh-mu/cgroup.log       # 看开机那次到底看到了什么
dsh-muctl doctor | grep "instance cgroup tree"   # 缺树时这一行会给出修复命令
```

> 交付前建议**真的重启一次**再验 ✓ —— 这个故障只在"开机路径"上出现 ✓ 运行中 `restart` 是好的 ✓。

## 6.6 把一台**旧版本**机器迁到新版本（保留用户/实例/对话，不保留 provider 与套餐）

真实场景：客户机跑 0.28.1，要升到现在。要留：用户 ✓ 实例 ✓ 出网规则 ✓
DSH 对话数据 ✓ 工作文件 ✓；**不留**：provider 包 ✗ 套餐 ✗（里面是钱 ✗）。

> 0.28.1 的 `backup` **本来就不含** provider 和套餐（它们今天才被加进备份成员表），
> 所以这一步不需要任何排除参数 ✓ 也不需要升级旧机的 CLI ✓。

### 6.6.1 旧机上：停服务 + 备份

```sh
for s in /etc/init.d/dsh-mu-*; do rc-service "$(basename "$s")" stop >/dev/null 2>&1; done
dsh-muctl backup --with-instances --out /root/old.tgz
#   --with-instances 是必须的：没有它备份里只有"记录"，home（对话/凭据/profile）与
#   workspace（用户的工作文件）都不会进档 ✓
#   备份格式号是 1，多年未变 ✓ 新 CLI 可以直接读 ✓
```

### 6.6.2 旧机上：清空

```sh
apk del dsh-mu
rm -rf /etc/dsh-mu /var/lib/dsh-mu /var/log/dsh-mu /usr/local/lib/dsh-mu \
       /usr/local/sbin/dsh-mu-jail /usr/local/sbin/dsh-mu-cgroup-init \
       /etc/init.d/dsh-mu-* /etc/logrotate.d/dsh-mu /usr/share/doc/dsh-mu
```

> 新版本里有 `sh tools/purge-dsh-mu.sh`（默认干跑 ✓ 加 `--yes` 才删 ✓），
> 但它**随新包才存在** —— 旧机上按上面几条手删即可 ✓。

### 6.6.3 新机上：装 + 恢复

```sh
apk add --allow-untrusted /root/dsh-mu-0.90.1-r0.apk
dsh-muctl install
dsh-muctl runtime fix-pty

dsh-muctl restore /root/old.tgz --force
dsh-muctl config models_native false     # 旧 config 会把原生模型页重新打开
dsh-muctl config models_lock false       # 旧 config 会把已退役的补丁重新打上
dsh-muctl sync
dsh-muctl instance rebuild <每个实例>     # 关键一步，见下
```

### 6.6.4 为什么必须有 `instance rebuild`

备份**不含 jail rootfs**（每个 ~190MB 的可重建系统镜像）✓ 所以恢复回来的实例只有
**记录 + home + workspace** ✓ 没有 `instances/<n>/rootfs` ✗ → 直接启动会失败 ✗。

```sh
dsh-muctl instance rebuild demo
#   · 用当前模板重新铺 rootfs ✓
#   · 保留 home / workspace（实测：先放一个标记文件，重建后仍在 ✓）
#   · 重渲服务 / 实例配置 / 计划 patch，修属主 ✓
#   · 原来在运行的实例自动拉起 ✓
```

### 6.6.5 不需要做的事（省得绕路）

- **不用建 OS 账号**：实例跑在 `uid 0`，`user add` 只写 state 里的密码哈希 ✓
  （`adduser` 只用于 nginx 那个服务账号 ✓）。
- **不用排除 provider/套餐**：旧机备份本来就没有 ✓。
- **不用管套餐缺省值**：没有套餐的实例会得到 `[]` 这个合法 patch ✓（0.89.0 修的 ✗ 之前是空文件 ✗）。

### 6.6.6 验收

```sh
dsh-muctl doctor            # 期望 0 FAIL
reboot                      # 验开机路径（cgroup / 实例自启）
dsh-muctl doctor
# 然后前台登录发一条消息 ✓
```

## 7. 验收清单（全绿才算装好）

```sh
dsh-muctl doctor                     # 0 FAIL
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:80/login   # 200
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:<port>/    # 401
ls /var/lib/dsh-mu/instances/<n>/home/.dsh/profiles/web/node_modules    # 有 @dsh-mu/*
```

最后：浏览器登录 → 发一条消息 → 有回复 ✓（这一步只能人做）。
