# 12 · 干净机复现清单（给人照着走）

> 目标：在一台**全新 Alpine** 上，从零走到"平台跑起来 + 模型接入可用"，并顺便验证
> "AI 生成的 provider 配置文件能不能直接导入"。每一步都给了**期望输出**，对不上就停。

## 0. 准备

| 项 | 要求 |
|---|---|
| 系统 | Alpine 3.2x（LXC 或裸机均可），root |
| 宿主依赖 | 只有 **python3 / util-linux / curl / ca-certificates**（+ 可选 logrotate）。**宿主不需要 node/npm/dsh** —— DSH 运行时装在网关模板里 |
| 资源 | ≥ 2 GB 内存、≥ 8 GB 磁盘（实例模板 140 MB/个，平台 jail 214 MB） |
| 网络 | 能到 `mirrors.tuna.tsinghua.edu.cn`（或官方源）、`registry.npmjs.org` |
| 凭据 | 至少一把真实 key：DeepSeek 或 opencode go（测"AI 生成配置"时用后者更全面，它三种协议都有） |
| 浏览器 | 访问 `http://<机器IP>/login` 与 `http://<机器IP>/admin/` |

> 宿主机**不需要** nginx / openresty —— 网关跑在平台 jail 里。

## 1. 装包（未签名 v3）

```sh
apk add --allow-untrusted /path/to/dsh-mu-0.1.21-r0.apk
```

期望：`OK: … MiB in … packages`；`dsh-muctl --version` 有输出。
若报 `v2 package format error`，说明 apk-tools 是 2.x —— 需要 Alpine 3.22+。

## 2. 初始化平台

```sh
dsh-muctl install
```

期望（按顺序出现的关键行）：

```
mirrors: public address looks like CN; using the Tsinghua mirrors
using the newest image: alpine-3.2x-default_…_x86_64.tar.xz
template built: /var/lib/dsh-mu/templates/alpine (140 MB) from alpine-…
gateway_mode=jail: building the platform jail (openresty inside)
template built: /var/lib/dsh-mu/templates/gateway (214 MB) from alpine-…
host openresty stopped so the jail can take the port      ← 只在宿主机有 openresty 时
gateway jail is answering on port 80 (HTTP 200)
install complete
```

**这一步最容易卡住的三个点**：

1. 宿主没有 `xz` —— 平台用 Python `tarfile` 解压，不需要 xz ✓（若你看到 `xz: Cannot exec`，说明包是旧的）。
2. 交互提示**不会**在脚本里触发（stdin/stdout 都不是 tty 时用默认值）；要静默就 `DSHMU_NONINTERACTIVE=1`。
3. 模板下载失败会**回落到官方源**；两个都失败会直接报错（不会留半成品）。

## 2.0 运行时都在 jail 里（2026-10-19）

| 组件 | 在哪 |
|---|---|
| `dsh-muctl` / `dsh-mud` | 宿主（python3 即可） |
| **DSH 运行时**（`@deepseek-ai/dsh` + node/npm） | **网关模板**：`/var/lib/dsh-mu/gateway/rootfs/usr/local/lib/node_modules/@deepseek-ai/dsh` |
| 实例的运行环境（node/npm/pnpm） | 各实例自己的模板 |
| 网关（openresty + Lua） | 平台 jail |

- 实例以**只读**方式挂载网关模板里的那份运行时，**一份包、多个实例共享**
- 升级 DSH = `dsh-muctl install --force-dsh`（在网关模板里 chroot 跑 npm），**重启实例**后生效
- 实例启动命令是 `exec node <runtime>/lib/bin.js …`（不再依赖 PATH 里有 `dsh` 这个二进制）
- 因此：宿主机可以完全没有 node ✓；**P2 的用量统计、轮询代理如果要用 node，也放网关 jail** ✓

## 2.1 两条手工安装才会遇到的说明（2026-10-18）

- **`user add` 会自动建实例并启动它**，所以手册里不需要再跑 `dsh-muctl instance create alice`
  （再跑只会得到 `instance alice already exists`）。`instance create` 只用于"给已有用户加第二个实例"。
- **镜像下载（2026-10-18 定稿）**：同一地址 `curl` 能下、`busybox wget` 会 **403**；
  而全新机器上**没有 curl**（只有 busybox wget）。所以现在：
  1. **用 python3/urllib 下载**（python3 是硬依赖，行为等同 curl），并打印**进度**
     （`0.2 MB / 3.2 MB (7%, 1.0 MB/s)` … `downloaded 3.2 MB in 0.3s`）；
  2. 顺序是 **TUNA → USTC → 你配的基址 → 官方**（官方在 CN 网络可能极慢，不能排前面）；
  3. python 不可用时才退回 curl / wget；每个候选都有超时，失败会打印 `downloading …` 再试下一个。
  实测（本机）：TUNA 经 python **0.3 秒**下完 3,314,972 字节。
- **首次启动可能超过 5 分钟**（要在 jail 里 `npm install` 整个 DSH profile），等待上限已提到 900 秒；
  若真的失败，`instance start` 现在会把 harness 自己的原因打出来（例如
  `the harness refused to start -> dsh: startup failed: … DUPLICATE_KEY …`）。

## 3. 自检

```sh
dsh-muctl doctor
```

期望最后一行 **`0 FAIL`**（PASS 数随环境在 31–33 之间浮动，不要求固定值）：

- 只有 **jail** 模式了（默认且唯一推荐；`GATEWAY_MODE=host` 是遗留分支），所以宿主**不需要** nginx，
  `required commands` 也不会再要求它；
- WARN 一般是 `logrotate` 未安装、或某个可选探测失败，不影响使用；
- `gateway jail config  PASS  re-rendered: … differs` 是自愈（主机名/IP 列表变了），不是故障。

`gateway jail config` 若显示 `PASS  … re-rendered: … differs`，那是自愈（主机名/IP 列表变了），不是故障。

## 4. 建账号与实例

```sh
dsh-muctl user add alice --password 'alice-test-123'
dsh-muctl instance create alice
dsh-muctl instance status        # alice  running  ok
```

期望：`instance alice: upstream cookie refreshed (dsh-auth-…, value fingerprint …)`
（若出现 `could not mint a cookie now`，等 10 秒后 `dsh-muctl instance refresh-cookie alice`）

## 5. 模型接入：导入 AI 生成的配置

1. 后台 `http://<IP>/admin/` → **模型接入** → 「查看 / 复制」或「下载为文件」，把**规范 + 提示词**
   连同供应商文档丢给任意 AI（网页版即可，不需要它装任何工具）。
2. 把 AI 返回的 JSON 粘进「provider 配置（JSON）」→ 先点 **只校验**。
   - 报 `models[i].base_url already contains … path` → AI 把 `/v1` 或 `/chat/completions` 写进了
     `base_url`，让它去掉（`base_url` 只能是前缀）。
   - 报 `models[i].api must be one of …` → 只允许 `openai-completions` / `openai-responses` /
     `anthropic-messages`。
3. 点 **导入** → 期望 `已导入 <id>（N 个模型，默认 …）`。
4. 该行点 **刷新模型**（可填 key）→ 期望 `刷新完成：上游 N 个，新增 M 个，共 K 个`；
   点 **查配额** → 若供应商有 usage 接口，会弹出 `rolling/weekly/monthly xx% + 重置时间`。

## 6. 建团队套餐

后台「团队套餐」→ 填：套餐名（会成为**模型选择器里的分组名**）、provider、key、
可见用户（留空=全部）、限定模型（可选）、设为默认 → **创建套餐**。

```sh
dsh-muctl plan list
# plan_xxxxxxxx   <套餐名>  <provider>  团队  key=yes models=N on *默认
```

然后：

```sh
dsh-muctl instance restart alice
```

期望：`upstream cookie refreshed (… fingerprint …)` + `GET /` 200。

> 多 `base_url` 的 provider（如 opencode-go）会渲染成**两个分组**：
> `<套餐名> · chat` 与 `<套餐名> · messages` —— 这是 pi-ai 一条路由只能一个 baseURL 的必然结果。

## 7. 用户侧

1. 浏览器 `http://<IP>/login` → alice 登录 → 进入自己的实例。
2. 左侧边缘的小图标（1:1 的 35×76，无阴影）→ 打开抽屉 → **我的套餐**：
   团队套餐显示「只读」，可以「添加我的套餐」（名字 + provider + key）。
3. 模型下拉应出现分组 `<套餐名>`（或 `· chat` / `· messages`）；切换分组即切换**配额**。

## 8.1 手工安装反馈的修正（2026-10-18）

第二轮手工安装后修的 6 件事：

| 反馈 | 根因 | 修法 |
|---|---|---|
| **A** `npm install -g dsh` 很慢 | 只在建模板时才做区域判断，全局 npm 安装跑在默认 registry 上；而这台机的 IP 归属查询**失败**（返回 None） | 安装一开始就决定 registry：先看区域，查不到就**实测两家的 `/-/ping` 延迟**取快者；日志打印选择与理由 |
| **A** 模板下载慢、TUNA 像没成功 | TUNA 的 proxmox 目录对这份树返回 **403**，而旧代码仍然先试它（busybox wget 无超时，会干等） | 下载前**先探测**各镜像（含 USTC），不可用的打印 `skipping mirror …` 并跳过；curl/wget 都加了超时 |
| **B** 提示重复、看不懂在选什么 | 区域判断与镜像选择在两次模板构建里各做一遍 | 区域探测与镜像决策**每进程只做一次**（缓存）；两个模板的日志分别写「运行环境模板（用户实例用）」/「网关模板（平台 jail 用，含 openresty）」 |
| **C** doctor 31 与手册 35 不一致 | 只有 jail 模式了，宿主机本来就没有 nginx，检查项随之减少 | 文档改为「**0 FAIL** 才是关键，PASS 数随环境 31–33」，并说明 WARN 的含义 |
| **D** 登录提示"实例凭据未就绪" | `user add` / `instance create` 只落盘不启动，没有 upstream cookie | 两者默认**创建后立刻启动**并 mint cookie（`--no-start` 可关） |
| **E** root 登录后台"用户名或密码错误" | 校验走 `busybox cryptpw`（复现不了 `$6$`）+ `openssl passwd`（**没装**）→ 必然失败 | 用**纯 Python 的 sha512-crypt** 校验（对着官方测试向量验证过），外部工具只作兜底 |

实测（本机）：`right password → 200 ok:True`、`wrong password → 401`；`user add bob2` 后实例
**自动 running 且 cookie=yes**；镜像探测跳过 TUNA、官方源几秒下完。

## 8.2 干净机实测记录（2026-10-18，Alpine 3.24.1）

第一次在真正干净的机器上跑，抓到 4 个**只在全新环境**才暴露的 bug（都已修）：

| 现象 | 根因 | 修法 |
|---|---|---|
| 装完 `dsh-muctl` 报 `env: can't execute 'python3'` | `apk mkpkg` 的 `-I depends:` **重复给出只保留最后一个**，且逗号列表会被当成一个包名 | 改成**一条** `-I "depends:python3 nodejs npm pnpm util-linux logrotate"`（空格分隔） |
| `install` 报 `UnboundLocalError: host_nginx` | install 的 jail 分支被两次补丁叠乱：`host_nginx` 在赋值前使用、`restart` 在健康检查之后 | 整段重写为「判定 → 停宿主 nginx → 建 jail → 重启 → 健康检查 → 失败回滚」 |
| 平台 jail 的 rootfs 只有 1 MB | `gateway_paths()` 先建了空目录，导致"要不要复制模板"的判断永假 | 改看内容：`rootfs/usr/sbin/nginx` 是否存在 |
| 安装后 `/` 一直 503（直连 3100 却 200） | jail 里的 `/etc/dsh-mu` 副本只在 `sync_all` 时刷新，状态变了就变旧（cookie 为空） | `render_gateway()` 里同步刷新该副本 |
| doctor 报 `required commands: missing: nginx` | 宿主机确实没有 nginx（jail 模式故意如此） | 该项在 jail 模式下不再要求 nginx |

最终状态（实机）：

```
doctor: 32 PASS, 1 WARN, 0 FAIL
:80     0.0.0.0:80 LISTEN 1970/nginx.conf      ← 平台 jail 里的 nginx
dsh-mud 127.0.0.1:8787
/admin/ -> 302   /login -> 200   /mu-static/panel.js -> 200
日志: 模板 140MB + 网关模板 214MB + 网关 rootfs 214MB + 实例 rootfs 140MB
```

## 8.3 实例内工具链与"红字错误"的归属（2026-10-18）

模板内现在会装 **ripgrep**（harness 的 `glob`/`grep` 工具依赖它）和 **procps**（`ps`）。
缺 ripgrep 时表现为对话里 `查找文件 · Error: glob subprocess failed … (ripgrep provider failure)`。
已经存在的实例可以现场补：

```sh
R=/var/lib/dsh-mu/instances/<name>/rootfs
mount -t proc proc $R/proc; chroot $R /sbin/apk add --no-cache ripgrep procps; umount $R/proc
```

对话里出现红字时，先分清归属：

| 提示 | 归属 |
|---|---|
| `glob subprocess failed … (ripgrep provider failure)` | **平台**：实例缺 ripgrep（已修） |
| `spawn bash ENOENT` | **平台**：多为工作目录/proc 未就绪的瞬时错误；若反复出现，`instance exec <name> -- ls -la /home/dsh` 核对 |
| `old_string and new_string must differ` | **模型**：它自己给的编辑参数不合法，换模型或让它重试 |
| 5xx / 超时 / 长时间无响应 | **上游**：中转站或供应商；用「查配额」和直连同一 key 对照 |

## 9. 出问题时先看这几处

| 现象 | 先看 |
|---|---|
| 页面 502/504 | `dsh-muctl gateway jail-status`、`dsh-muctl gateway logs` |
| 页面 401（`dsh web authentication required`） | `dsh-muctl instance refresh-cookie <name>`；若无效，检查实例 `~/.dsh/.credentials.yaml` 里 `records:` 是否还在（丢了就会 401） |
| 模型 401/400 | `dsh-muctl provider validate`、后台「查配额」是否也失败（key 本身的问题） |
| `ModelProtocolUnsupported` | 该模型要走别的协议：在模型上写 `api`，必要时再写它的 `base_url` |
| 实例起不来 | `dsh-muctl instance logs <name> --lines 200` |
