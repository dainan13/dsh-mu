# 07 · 客户机重装步骤（从"现在的烂摊子"到"干净可用"）

> 这份是给**现场执行**用的：先清理，再按顺序装，每一步都有判据。
> 前提：你手上有 `dsh-mu-0.90.1-r0.apk`（或更新）。

## 0. 准备

```sh
# 把 apk 和清理脚本放到 /root
ls -l /root/dsh-mu-0.90.1-r0.apk /root/purge-dsh-mu-standalone.sh
```

## 1. 清理（先干跑，看清楚再真删）

```sh
sh /root/purge-dsh-mu-standalone.sh            # 只打印，不动手
sh /root/purge-dsh-mu-standalone.sh --yes      # 真删
```

**干跑时你应该看到**：要停的服务（`dsh-mu-*`、`dsh-mud`）、要杀的进程（`dsh-mu-jail`、
`nginx: master`、`@deepseek-ai/dsh/lib/bin.js`、`dsh-mud`）、要删的目录
（`/etc/dsh-mu`、`/var/lib/dsh-mu`、`/var/log/dsh-mu`、`/usr/local/lib/dsh-mu` …）。

**判据（三条全空）**

```sh
ls -d /etc/dsh-mu /var/lib/dsh-mu /var/log/dsh-mu 2>/dev/null || echo "目录已清 ✓"
ps aux | grep -cE "[d]sh-mu-jail|[n]ginx: master|[@]deepseek-ai/dsh/lib/bin.js"   # 0
ls -d /sys/fs/cgroup/dsh-mu 2>/dev/null || echo "cgroup 树已清 ✓"
```

## 2. 装（顺序不能换）

```sh
apk add --allow-untrusted /root/dsh-mu-0.90.1-r0.apk
dsh-muctl install
```

**判据（`install` 必须走到最后一行）**

- 输出里应有 `generated /etc/dsh-mu/admin.token`、`shared runtime ready: …`、`install complete`
- 最后一行 `doctor: … 0 FAIL`
- **不能**出现 `nginx: [emerg]` 或 `install` 半途中止

```sh
grep -c "generated by dsh-muctl" /var/lib/dsh-mu/gateway/conf/nginx.conf   # ≥1 ✓ 新模板
ls -ln /var/lib/dsh-mu/gateway/rootfs/var/tmp/nginx | head -5              # 属主 0 0 ✓
```

## 3. 修 pty（musl 上必须）

```sh
dsh-muctl runtime fix-pty
```

## 4. 起网关 + 验登录页

```sh
dsh-muctl gateway restart
sleep 5
ss -ltn 2>/dev/null | grep -E ":(80|443)" && echo "网关在听 ✓"
tail -3 /var/log/dsh-mu/__gateway.err.log     # 不应有 chown/emerg ✓
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:80/login   # 200 ✓
```

> 密码：admin 用**系统账号**（一般是 `root`）的密码。没设过就先 `passwd root`。

## 5. 建第一个用户与实例

```sh
dsh-muctl user add demo --password '<口令>'
dsh-muctl instance create demo --user demo --cpu "50000 100000" --mem 536870912 --pids 128
dsh-muctl sync
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:3100/   # 401 ✓
```

浏览器登录 `demo` → 应该能进自己的实例 ✓（发一条消息验证模型链路 ✓）。

## 6. 重启一次（**必做**，验开机路径）

```sh
reboot
# 起来后
dsh-muctl doctor | grep -E "cgroup|^FAIL|^doctor:"
tail -3 /var/log/dsh-mu/cgroup.log            # 开机自证：mount=cgroup2 / limits=yes ✓
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1:3100/   # 401 ✓ 实例自启 ✓
```

## 7. 如果要恢复旧数据（可选）

```sh
# 手工 tar（不含 provider/套餐/rootfs）解包到 /
cd / && tar xzf /root/old.tgz
dsh-muctl install                      # ← 关键：重渲染 nginx.conf/gateway.conf/服务
dsh-muctl config models_native false
dsh-muctl config models_lock false
dsh-muctl sync
dsh-muctl instance status | tail -10    # 看有哪些实例
dsh-muctl instance rebuild <每个实例>    # 重建 rootfs，保留 home/workspace
dsh-muctl gateway restart
dsh-muctl doctor | grep -E "^FAIL|^doctor:"
```

## 8. 这轮踩过的坑（记住就不会再踩）

| 坑 | 症状 | 正确做法 |
|---|---|---|
| 停不干净 | `rc-service stop` 后还在跑 `nginx: master` / `dsh-mu-jail` | 用清理脚本（cgroup.kill + pkill）✓ |
| 令牌缓存空值 | token 文件在，却一直 “no admin token” | `dsh-muctl gateway restart`（0.90.2 起会真停）✓ |
| 登录限流 | 刚错几次就 “尝试次数过多” | 同上；0.90.2 会提示等多久 ✓ |
| 旧渲染产物 | 网关 `chown … Operation not permitted` 反复重启 | 解包后 **必须** `dsh-muctl install` 重渲染 ✓ |
| 无 rootfs | 恢复的实例起不来 | `dsh-muctl instance rebuild <名字>` ✓ |
| 空 patch | 无套餐实例报 `must be a top-level YAML array` | 0.89.0 起写 `[]` ✓ |
| 备份被断链中断 | `backup` 报 `node_modules/.bin/…` 不存在 | 用不带 `-h` 的 `tar` 手工备份 ✓ |

# 附 A · **已实测通过**的现场步骤：只保留用户 + 对话数据（推荐）

在实验室上，用**客户真实备份**（9 用户 / 8 实例 / 96 个会话）从零跑通：
`doctor 59 PASS / 5 WARN / 0 FAIL`、`/login = 200`、8 个实例全 `401`、运行时 `0.2.1-rc.5`（未降级）。

## A.1 准备好三个文件（放在客户机 `/root/`）

```
/root/dsh-mu-0.91.0-r0.apk
/root/migrate-users-only.sh
/root/<旧机备份>.tgz            # 只有 state.json + instances/*/home + */workspace 就够
```

## A.2 跑（先干跑，再真跑）

```sh
sh /root/migrate-users-only.sh /root/<备份>.tgz /root/dsh-mu-0.91.0-r0.apk
sh /root/migrate-users-only.sh /root/<备份>.tgz /root/dsh-mu-0.91.0-r0.apk --yes
```

脚本内部（8 步，全自动）：

1. 停服务 → `cgroup.kill` → `pkill` → **按 `/proc/*/exe` 跨命名空间杀残留 nginx/jail** → 删平台目录 → `apk del`
2. `apk add` 新包 → `dsh-muctl install`
3. **只**恢复 `etc/dsh-mu/state.json` 与 `var/lib/dsh-mu/instances`
4. 再 `install`（重渲染 nginx.conf / gateway.conf / 服务 / admin.token）
5. `config models_native false`、`models_lock false`、`runtime fix-pty`、`sync`
6. 逐实例 `instance rebuild`（重建 rootfs，保留 home/workspace）
7. 抢端口自检 → 起网关 → 端口 401 验收 → doctor
8. 打印平台版本 / 运行时版本 / 配置里的 `dsh_version`

## A.3 现场只看三条

```sh
dsh-muctl doctor | grep -E "^FAIL|^doctor:"                        # 期望 0 FAIL
curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1/login    # 期望 200
for p in 3100 3101 3102 3103 3104 3105 3106 3107; do \
  printf "%s -> " "$p"; curl -s -o /dev/null -w "%{http_code}\n" "http://127.0.0.1:$p/"; done   # 期望全 401
```

## A.4 两个**必须知道**的坑（都已在脚本里规避）

1. **不要恢复 `dsh-mu.conf`** ✗
   旧机的 conf 钉着 `dsh_version=0.2.0-rc.2`，`install` 会照着它把运行时**降级** ✗。
   脚本不恢复 conf ✓ 所以运行时留在新默认 `0.2.1-rc.5` ✓。
2. **`ss` 不可信** ✗
   有的机器上 `ss -ltn` 什么也列不出来（连 nginx 自己的监听都不显示），
   会让人误以为"网关没起"。判断网关只信：
   ```sh
   curl -s -o /dev/null -w "%{http_code}\n" http://127.0.0.1/login   # 200 = 起来了
   ```

## A.5 迁移后用户没有套餐（预期）

provider 与套餐按设计丢弃 ✓。`install` 会自动建一个 keyless 的 Kilo 默认套餐
（`plan_default`，对所有用户可见）✓，所以用户能立刻发消息；
要换成用户自己的 key，后台「模型接入」再配即可。

## A.6 想保留更多东西时

| 想保留 | 做法 |
|---|---|
| 出网规则 | 备份里不放，迁移后后台「平台 → 出网」重新配（或 `dsh-muctl egress …`） |
| 网关证书 | 迁移后重新签发（自签），或把旧 `tls/` 单独拷回 `/etc/dsh-mu/tls` 再 `install` |
| provider / 套餐 | 重新导入（后台「模型接入 → 从 DSH 目录添加」） |
