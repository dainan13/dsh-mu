# dsh-mu 架构设计（实现契约）v1.0

> 前置：`docs/01-需求整理.md`。本文只记录**已确认**的设计决策与实现契约。

## 1. 已确认决策

| 编号 | 决策 | 含义 |
|---|---|---|
| A1 | 代理层 = **纯 openresty + Lua** | 登录页、会话、路由、上游 cookie 代持全在 nginx 内完成，无额外常驻进程 |
| A2 | 管理面 = **服务端 CLI**（`dsh-muctl`，Python3 标准库） | 用户/实例/安装/限额/日志全部终端管理，另暴露 `/mu-api/`（仅 loopback）供脚本调用 |
| A3 | ~~不做 Web 管理界面（本期）~~ → **已被 M3 取代** | 现已有 `dsh-mud` 回环后端 + 网关 `/admin/` + 管理页面（见 §10） |
| A4 | 隔离 = mount ns + chroot + cgroup v2，**无 PID ns、无 net ns** | 进程列表与网络共享宿主，目录与 apk 环境隔离 |
| A5 | rootfs 策略 = 每实例独立 rootfs 拷贝；**DSH 全局包共享只读** | jail 内 apk 装 node/pnpm，`@deepseek-ai/dsh` 从宿主只读绑定 |
| A6 | 鉴权 = 本地账号（管理员创建），密码散列，平台会话 cookie | 网关自己的会话，与 DSH 上游 cookie 分离；**管理员已改为宿主系统账号**（见 §10.1） |
| A7 | 模型 key = 平台统一 key，建实例时注入该实例 `DSH_HOME` | 用户无感 |
| A8 | 「设置」分区不可用 → 本期接受 | `ownsHost` 仅 shell-owned transport 可设，服务页面无解，除非改客户端源码 |
| A9 | 进程守护 = 每实例一个 OpenRC 服务 | 复用系统 init 的 respawn/开机自启，无需自写守护进程 |

## 2. 组件与数据流

```
浏览器 ──http://dsh-mu/──► openresty :80
                            ├─ /login /logout        → lua/login.lua（自渲染 HTML）
                            ├─ /mu-api/*             → lua/api.lua（allow 127.0.0.1）
                            └─ /                     → access_by_lua_file lua/auth.lua
                                                        │ 读 gw_users.json / gw_upstreams.json
                                                        ▼
                                          proxy_pass http://127.0.0.1:<port>
                                          Host/Origin 重写为同一 loopback authority
                                          Cookie 注入为上游实例自己的 dsh-auth-*
                                                        ▼
                                          jail 内 dsh web（mount ns + chroot + cgroup）

dsh-muctl (python3)  ──写──► /etc/dsh-mu/state.json            （唯一事实源，含口令散列）
                     ──渲染─► /etc/dsh-mu/gateway/users.json    （Lua 只读）
                     ──渲染─► /etc/dsh-mu/gateway/upstreams.json（Lua 只读）
                     ──渲染─► /etc/dsh-mu/instances/<n>.conf    （jail runner 只读）
                     ──写──► /etc/init.d/dsh-mu-<n> + /etc/conf.d/dsh-mu-<n>（OpenRC 服务）
                     ──调用─► rc-service / rc-update（启停与开机自启）
```

## 3. 网关（openresty + Lua）

### 3.1 Nginx 关键配置

```nginx
lua_shared_dict dshmu 8m;              # 状态缓存 + 登录限速计数
lua_package_path "/usr/local/lib/dsh-mu/lua/?.lua;;";
map $http_upgrade $connection_upgrade { default upgrade; '' close; }

server {
  listen 80 default_server;
  client_max_body_size 512m;
  location = /login  { content_by_lua_file /usr/local/lib/dsh-mu/lua/login.lua; }
  location = /logout { content_by_lua_file /usr/local/lib/dsh-mu/lua/logout.lua; }
  location ^~ /mu-api/ { allow 127.0.0.1; deny all; content_by_lua_file .../api.lua; }
  location / {
    set $gw_upstream "";                # 由 auth.lua 填充，如 127.0.0.1:3101
    set $gw_cookie   "";                # 上游实例的 dsh-auth-* cookie
    set $gw_user     "";
    access_by_lua_file /usr/local/lib/dsh-mu/lua/auth.lua;
    proxy_pass http://$gw_upstream;     # 变量化上游 → 改端口不需 reload
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection $connection_upgrade;
    proxy_set_header Host $gw_upstream;
    proxy_set_header Origin http://$gw_upstream;
    proxy_set_header Cookie $gw_cookie;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-DSH-MU-User $gw_user;
    proxy_buffering off; proxy_read_timeout 3600s; proxy_send_timeout 3600s;
  }
}
```

- **上游 Host/Origin 归一化**：固定为 `127.0.0.1:<port>`。DSH 的 `/api` 信任栅栏对 loopback 自动放行，且 `Origin == Host` 检查自然通过（`dsh-client-connection` `isTrustedApiRequest`）。
- 511/502/504 → 友好 503 页（`error_page` 指向 lua 渲染的提示页）。
- `Host` 重写后浏览器看不到上游；上游 cookie 由网关注入，浏览器只持有平台会话 cookie。

### 3.2 平台会话 cookie

名称 `dshmu_session`，值 `v1.<b64url(payload)>.<b64url(hmac_sha256(secret, b64url(payload)))>`：

```json
{"v":1,"u":"alice","e":3,"sid":"<16B hex>","iat":1700000000,"exp":1700003600}
```

- `secret` = `/etc/dsh-mu/secret.key`（32B 随机，0600，`dsh-muctl init` 生成）。
- `e` = 用户 `epoch`；改密/强制下线/禁用会自增 epoch，使旧 token 立即失效（**无状态撤销**）。
- 校验顺序：签名 → 未过期 → `gw_users.json` 中用户存在且 `enabled`、`epoch` 匹配 → 实例存在且 `state==running`。
- Cookie 属性：`HttpOnly; SameSite=Lax; Path=/; Max-Age=...`。登录成功重定向回 `next`（只接受以 `/` 开头且不含 `//` 的路径）。

### 3.3 口令散列

`<algo>$<params>$<salt_b64>$<hash_b64>`，`dsh-muctl` 与 Lua 两侧实现一致：

| algo | 参数 | Python | Lua |
|---|---|---|---|
| `pbkdf2sha256` | `iter=20000,dklen=32` | `hashlib.pbkdf2_hmac` | `resty.hmac` 循环 |
| `scrypt` | `n=16384,r=8,p=1,dklen=32` | `hashlib.scrypt` | `resty.openssl.kdf.derive` |

默认算法在 M1 实测 Lua 侧性能后确定（见 §7 待验证项）；两种算法 Lua 侧都要支持，便于切换。

### 3.4 登录限速

`lua_shared_dict` 计数：key = `user:<name>` 与 `ip:<addr>`，10 分钟内失败 10 次 → 锁定 10 分钟，返回 429。

## 4. 状态文件

| 文件 | 写入者 | 读取者 | 内容 |
|---|---|---|---|
| `/etc/dsh-mu/state.json` | CLI | CLI | 用户（含口令散列、role、enabled、epoch、instance）+ 实例（端口、路径、限额、uid/gid、上游 cookie） |
| `/etc/dsh-mu/secret.key` | CLI | Lua/CLI | 32B HMAC 密钥（0640 root:nginx） |
| `/etc/dsh-mu/gateway/users.json` | CLI | Lua | `{name:{pw,enabled,epoch,role,instance}}`，0640 root:nginx |
| `/etc/dsh-mu/gateway/upstreams.json` | CLI | Lua | `{name:{host,port,cookie,state,user}}`，0640 root:nginx |
| `/etc/dsh-mu/gateway/config.json` | CLI | Lua | 网关侧无秘密配置（`gateway_host`、`session_days`） |

> 口令散列放在网关视图里是必要的：登录校验发生在 nginx worker（uid `nginx`）内，
> 而 `state.json` 是 `0600 root`。该 worker 本来就持有会话签名密钥，因此散列不带来新的暴露面；
> 真正的防线是登录限速与口令强度。

| `/etc/dsh-mu/instances/<n>.conf` | CLI | jail runner | `sh` 可 source 的 `KEY=value`：`ROOTFS/HOME/WORKDIR/UID/GID/PORT/NAME/CPU_MAX/MEM_MAX/PIDS_MAX/EXTRA_MOUNTS` |
| `/etc/init.d/dsh-mu-<n>`、`/etc/conf.d/dsh-mu-<n>` | CLI | OpenRC | 每实例服务（`supervise-daemon`，respawn） |

Lua 侧加载：`ngx.shared.dshmu` 缓存 + 2 秒 TTL（无 `lfs`，不做 mtime 判断），配置改动 ≤2s 生效。

## 5. 实例 jail

### 5.1 启动序列（`/usr/local/sbin/dsh-mu-jail <name>`）

0. （开机由 `dsh-mu-cgroup` 服务执行，见 §5.4）委派 cgroup 控制器到 `/sys/fs/cgroup/dsh-mu`。
1. source `<n>.conf`；`mkdir -p /sys/fs/cgroup/dsh-mu/<n>`；写 `memory.max` / `memory.high` / `cpu.max` / `pids.max`（幂等）。
2. `unshare --mount --uts --propagation private --fork` 进入新 mount+UTS ns，`hostname <name>.dsh-mu`。
3. bind 挂载（`rbind` + 按需 `ro`）：`/proc`、`/sys`(ro)、`/dev`、`/dev/pts`、`/dev/shm`、宿主机 `/etc/resolv.conf`(ro, 若 jail 内不存在)、`/etc/localtime`(ro)、DSH 运行时 `/usr/local/lib/node_modules/@deepseek-ai/dsh`(ro)、持久卷 `home/`→`/home/dsh`、`workspace/`→`/home/dsh/workspace`、`/tmp` 私有 tmpfs（64m，nosuid,nodev）。
4. `echo $$ > /sys/fs/cgroup/dsh-mu/<n>/cgroup.procs`（此后所有子进程自动落在同组）。
5. `chroot <rootfs>`；`setpriv --reuid --regid --clear-groups --bounding-set=-all --inh-caps=-all --ambient-caps=-all --no-new-privs`（是否保留 uid 0 见 §7）。
6. `exec dsh web --host 127.0.0.1 --port <port> --no-open`，cwd = `/home/dsh/workspace`，`DSH_HOME=/home/dsh/.dsh`（持久卷内）。

### 5.2 rootfs 策略（决策 A5）

- **平台 jail** `/var/lib/dsh-mu/gateway/{rootfs,conf,logs,etc}`：网关（openresty）跑在里面，
  配置卷挂 `/etc/dsh-mu-gateway`、`/etc/dsh-mu` 用 jail 自己的副本（ro）、只保留 `CAP_NET_BIND_SERVICE`；
  `dsh-mud` 仍留在宿主（它要驱动 OpenRC/cgroup/chroot，见 `docs/10`）。
- 模板 `/var/lib/dsh-mu/templates/alpine/`：从 **Proxmox 系统镜像**（`alpine-<ver>-default_<date>_<arch>.tar.xz`，约 3 MB）
  下载解压而来（缓存于 `/var/lib/dsh-mu/images/`），随后把模板内 `/etc/apk/repositories` 指向 `ALPINE_MIRROR`，
  再 `chroot <模板> apk add <ALPINE_TEMPLATE_PACKAGES>`（真 chroot，包脚本/trigger 正常执行）；
  实例用户由 `/etc/passwd` 注入。镜像索引默认 `http://download.proxmox.com/images/system`（镜像站通常无法列目录），
  下载地址默认按公网 IP 归属地选（中国 → 清华 proxmox 镜像）；`ALPINE_TEMPLATE_IMAGE` 可钉死某个文件名。
- 建实例时 `cp -a` 模板 → `instances/<n>/rootfs`（实测单实例占用记入 README）。
- DSH 全局包**不装进 jail**，由宿主 `/usr/local/lib/node_modules/@deepseek-ai/dsh` 只读绑定（同路径），jail 内放 `/usr/local/bin/dsh` 软链。
- jail 内 `apk add/upgrade` 只改自身 rootfs，宿主与其它实例不受影响（验收标准 3）。

### 5.3 上游 cookie 代持

- 实例启动后，CLI 从实例日志抓 `http://127.0.0.1:<port>/?token=...`，以 `Host: 127.0.0.1:<port>` 回环发 `GET /?token=`，取 `Set-Cookie`，写入 `upstreams.json`。
- cookie 的 authority 恒为 `127.0.0.1:<port>`，与网关转发时的 Host 一致；签名密钥持久化在实例 `DSH_HOME`，实例重启后 cookie 仍有效。
- 端口变化或 `DSH_HOME` 重建 → `dsh-muctl instance refresh-cookie <name>` 重取。

### 5.4 cgroup 控制器委派（M1 实测得出的必需步骤）

容器内 cgroup namespace 根不是层级根，而是宿主上的普通 cgroup，且被 PID 1 与 console getty 占用，
直接写 `subtree_control` 会 `EBUSY`，子组里不会出现 `cpu.max/pids.max`。因此由
`/usr/local/sbin/dsh-mu-cgroup-init`（OpenRC 服务 `dsh-mu-cgroup`，runlevel `boot`，幂等）执行：

1. 把根组内的进程挪进 `/sys/fs/cgroup/init` 占位组（最多重试 5 轮）；
2. 打开根组 `subtree_control`；
3. 把 `cpu memory pids io` 委派给 `/sys/fs/cgroup/dsh-mu`。

每个实例服务都声明 `need dsh-mu-cgroup`，保证委派先于实例启动。实测限额生效证据见 `docs/03-M1-实测报告.md`。

## 9. M2 实测修正（与初版设计的差异）

实现过程中被实测推翻/补齐的设计点，均已落地：

| 原设计 | 实测结论 | 最终实现 |
|---|---|---|
| 实例以专用 uid（60001+）非 root 运行 | capability 全丢后 uid-0 不再有 `CAP_DAC_OVERRIDE`；非 root 时 jail 内 `apk add` 无法写自己的 apk 库；LXC 内 chroot 后再 `unshare(CLONE_NEWUSER)` 返回 EPERM | 实例以 **jail-root（uid 0，caps 全丢）** 运行；数据目录归属运行 uid；保留 `instance_run_uid` 配置位 |
| 只靠 `supervise-daemon` 停止实例 | 它只杀直接子进程，jail 内的 dsh 会变成孤儿并继续占端口 | 实例 init 脚本加 `stop_post()` 写 `cgroup.kill`；CLI 停止时同样兜底 |
| 绑定宿主 `/dev`、`/proc` | rw 绑定下 jail-root 可删宿主设备节点 / 写宿主 proc | 改为**私有 tmpfs /dev**（最小设备集 + 独立 devpts/shm）与**私有 procfs 实例** |
| DSH agent 沙箱沿用默认 | bwrap 需非特权 userns（LXC 禁）、Landlock 不可用（`EOPNOTSUPP`），DSH 沙箱 fail-closed → agent 的 bash 工具会不可用 | 实例以 `DSH_PERMISSION_MODE=danger-full-access` 运行（jail 即边界），可配置改回 |
| `users.json` 不含口令散列 | 登录校验在 nginx worker（uid `nginx`）内完成，读不到 `0600 root` 的 `state.json` | 散列放进 `users.json`（`0640 root:nginx`）；worker 本就持有会话签名密钥，无新增暴露面 |
| 模板软链 `.../@deepseek-ai/dsh/bin.js` | 实际入口是 `lib/bin.js` | 已改为 `lib/bin.js` |
| cgroup 控制器直接可用 | 容器 cgroup namespace 根被 PID 1/getty 占用 → `subtree_control` 写入 EBUSY | 新增 `dsh-mu-cgroup` OpenRC 服务：把根组进程挪进 `/init` 占位组后再委派 |
| `apk --root` 直接建模板 | 缺 `--keys-dir` 报 UNTRUSTED signature；jail 内 apk 也需要自带签名密钥 | 构建加 `--keys-dir /etc/apk/keys`，并把密钥复制进模板 |

# 10. 当前实现（M3 之后，与上文冲突处以本节为准）

上文 §1–§9 是 M1 的设计契约，部分已被后续迭代取代。本节记录**现状**。

## 10.1 身份与权限

| 角色 | 账号来源 | 口令校验 | 能力 |
|---|---|---|---|
| 管理员 | 宿主系统账号（`ADMIN_SYSTEM_USERS`，默认 `root`） | 后端以 root 读 `/etc/shadow` 比对（`openssl passwd -6 -stdin` / `busybox cryptpw -P 0`，口令不经 argv） | `/admin/` 页面与 API |
| 普通用户 | 平台账号（`dsh-muctl user add`） | 平台散列（PBKDF2-SHA256 / 可选 scrypt，见 `users.json`） | 只访问自己的实例与 `/me` |

- 平台账号**一律普通用户**；`users.json` 里系统账号的记录（`role=admin, pw=""`）由 `sync_all` 自动维护，供会话 epoch/enabled 校验；
- 旧的平台管理员角色会被自动降级，并在 `bootstrap`/`install` 输出里提示。

## 10.2 请求链路

```
浏览器 ──► openresty (:80, server_name 含本机名/IP)
   ├─ /login /logout         login.lua / logout.lua   （平台会话 cookie dshmu_session，HMAC v1）
   ├─ /                      auth.lua → proxy_pass http://127.0.0.1:<实例端口>
   │                           · Host/Origin 归一为 127.0.0.1:<port>（DSH /api 信任栅栏）
   │                           · 注入该实例的上游 cookie（网关代持）
   │                           · 端口探测失败 → 请求后端拉起 + 「实例正在启动…」自刷新页
   │                           · sub_filter 注入 <div id="dshmu-panel-root"> + /mu-static/panel.js
   ├─ /me                    me.lua（会话级 JSON：用户/角色/实例/运行状态）；
   │                          POST 改密或启动实例 → 内部通道转交后端
   ├─ /mu-static/*           panel.js / icon.png（用户面板资源）
   ├─ /mu-api/*              仅 loopback 的运维 API（脚本/自检用）
   ├─ /admin/                admin.lua 校验会话 + 系统管理员 → proxy_pass 127.0.0.1:8787
   │                          注入 X-DSH-MU-Admin(共享令牌) 与 X-DSH-MU-User(审计 actor)
   └─ /mu-internal/          网关自身子请求专用：?t=<令牌> 交后端校验（access_log off）
```

## 10.3 控制面

- **CLI**：`dsh-muctl`（14 行 shim）+ `dshmuctl.py`（库）。所有写操作走 `state_lock()`（flock，可重入）。
- **后端**：`dsh-mud`（Python 标准库，仅监听 `ADMIN_LISTEN`，默认 127.0.0.1:8787，OpenRC `supervise-daemon`）。
  **直接 import 同一个库**，因此 CLI 与页面行为一致；慢操作（start/restart/refresh-cookie）异步受理（202 + 审计）。
  注意：它启动时 import 一次库，**升级库文件后需 `dsh-muctl admin restart`**。
- **状态**：`/etc/dsh-mu/state.json`（用户/实例，schema 2，0600）；配置 `/etc/dsh-mu/dsh-mu.conf`（24 键，脚本可 source）；
  provider 目录 `/etc/dsh-mu/providers.json`；网关视图 `/etc/dsh-mu/gateway/{users,upstreams,config}.json`（0640 root:nginx）。
- **审计**：`/var/log/dsh-mu/audit.log`（JSONL：时间/操作者/动作/目标/详情/来源 IP；body 剔除 password/api_key）。

## 10.4 实例

- 每实例：独立 OpenRC 服务 `dsh-mu-<名>`、独立 rootfs 拷贝（`/var/lib/dsh-mu/instances/<名>/rootfs`）、
  home/workspace、cgroup `/sys/fs/cgroup/dsh-mu/<名>`、loopback 端口（`PORT_RANGE`）。
- 启动：`unshare --mount --uts --propagation private --fork` → 私有 tmpfs `/dev`（mknod + devpts + shm）
  → 私有 procfs → `/sys` 只读 → 放入 cgroup → `chroot` → `setpriv --bounding-set=-all --inh-caps=-all --ambient-caps=-all --no-new-privs`。
- 限额：`cpu.max`/`memory.max`/`pids.max`，CLI/页面对外是「核数 / MB / 进程数 / **不限(max)**」；
  运行中修改**立即生效**（cgroup v2 支持在线调整）。
- 端口：`dsh-muctl instance port <名> --port N [--restart]`（校验范围、实例间冲突、本机占用；
  `--restart` 会等新端口可连接后再返回）。状态判定是**服务感知**的（服务在跑即 running）。

## 10.5 用户面板与自动启动

- `gateway/static/panel.js`（Shadow DOM，避免与 Harness 样式互相污染）+ `icon.png`（左边缘探出的角色图标）；
- 抽屉内容：实例信息（名称/端口/实时状态/provider/模型）、未运行时「启动实例」、修改密码、退出登录；
- 数据 `GET /me`；动作 `POST /me`；
- **登录即自动启动**：`auth.lua` 探测到端口未监听时，经内部通道请后端拉起，并返回自刷新等待页。

## 10.6 打包与运维

- `packaging/APKBUILD` + `make-apk.sh`（优先 abuild，自动生成签名密钥；无 abuild 时手写打包器兜底）；
  包名 `dsh-mu`，`arch=noarch`，**不含** ~140MB jail 模板与任何 `/etc/dsh-mu`、`/var/lib` 内容；
- `apk add` → 打印三步提示；`dsh-muctl install` → 装依赖、全局装 DSH、构建模板、装网关片段、起服务、维护管理员账号、打印 doctor 摘要；
- `apk del` → 停服务、保留全部数据；重装后 `dsh-muctl install`/`doctor --fix` 会拉起 state 记为 running 的实例；
- 日志：`logrotate` drop-in（daily + maxsize 16M + copytruncate）+ `dsh-muctl logs rotate` 兜底；
- 自检：`dsh-muctl doctor`（30+ 项，随实例数增长；`--json`/`--fix`）；验收：`selftest` / `acceptance` / `tests/fresh-machine.py`。

## 10.7 隔离边界的验证（可重复）

隔离不是"设计上如此"，而是每次都能被测出来的。`tests/isolation.sh`（`sh tests/isolation.sh [实例] [--json]`）
会在**活着的实例内部**执行探针，逐条断言，并在 `tests/regression.sh` 里作为第 5 层自动运行。

实测结论（dsh-mu，alice/bob 各 20 项，`PASS=20 FAIL=0`）：

| 断言 | 结果 |
|---|---|
| chroot：宿主 `/etc/dsh-mu`、`/var/lib/dsh-mu` 在 jail 内不存在；jail 的可读 `/etc/shadow` 不等于宿主的 | ✅ |
| capability：`CapInh/Prm/Eff/Bnd/Amb` 全为 0 | ✅ |
| procfs magic link：`/proc/{1,dsh-mud,nginx-master}/root/...` 与 `environ` 全部拒绝 | ✅ |
| 写 `/proc/sys`、`mount`、`mknod`、`unshare -m` 全部拒绝 | ✅ |
| jail 自己的 rootfs 与 home **可写**（保留"jail 内 apk 装包"的能力） | ✅ |
| 共享 DSH runtime 只读（写入被拒） | ✅ |
| `/tmp` 为私有 tmpfs，jail 内写入不会出现在宿主 | ✅ |
| 进程位于 `dsh-mu/<实例>` cgroup，`cpu.max`/`memory.max`/`pids.max` 与记录一致 | ✅ |
| 跨租户：直连另一实例端口（含伪造 cookie）得到 401，运维 API 无令牌 403 | ✅ |

### 已知取舍（写进威胁模型，不是漏洞）

- **无网络命名空间**：实例可以 *连到* 彼此的 loopback 端口和平台的 8787。真正的鉴权是 DSH 自己的
  HMAC cookie（每个实例独有、无法伪造）与平台运维 API 的共享令牌，因此**拿不到别人的会话**；
  但端口的"存在性"与 401/302 响应对同机租户可见。
- **无 PID 命名空间**：`/proc` 里能看到宿主进程号（列表层面），但 `/proc/<pid>/root|environ` 受
  ptrace 权限检查保护，实测在"无 capability + uid 0"下依然被拒。
- 实例默认以 **jail-root（uid 0，能力全清）** 运行，以便在**自己的** rootfs 内自由 apk 装包；
  需要更严格时可以 `dsh-muctl config instance_run_uid auto`，让每个实例跑在独立宿主 uid 上
  （数据目录需相应 chown；jail 运行器已支持该分支）。

## 10.8 审计留痕的实现位置

审计不是"在每个命令里记得调一次"，而是**收敛到三个写入函数**上做差异比较，因此不可能漏：

| 写入函数 | 记录动作 | detail |
|---|---|---|
| `save_state()` | `state.change` | 账号/实例的 `added` / `removed` / `changed`（指纹含 role、enabled、绑定实例、must_change、口令散列前 16 字符、端口、状态、限额、provider、是否有凭据） |
| `save_config()` | `config.change` | 变更的**键名**列表（`model_api_key` 只记"已设置"，不记值） |
| `save_custom_providers()` | `provider.change` | provider 的 `added` / `removed` / `changed` |

每条还带 `cmd`（打码后的命令行；`--password/--api-key/--key/--token/--cookie/--model-api-key` 后的值
与长随机串一律 `***`）与 `actor`（`cli:<系统用户>@<主机>`，可用 `DSHMU_ACTOR` 覆盖）。

后端进程设置 `DSHMU_BACKEND=1` 时跳过这三类通用记录（避免与请求级记录重复），它自己写
`action=<路由名>` + 真实管理员 + 客户端 IP + 状态码 + **脱敏请求体**；`/api/instances/<n>/ensure`
仅在真的拉起实例时记录。

## 10.9 会话与跨站防护

| 层 | 机制 | 位置 |
|---|---|---|
| 会话 cookie | `HttpOnly; SameSite=Lax`，HMAC 签名、含 epoch（改密即失效） | `lua/dshmu.lua` |
| 登录 CSRF | 双提交：表单隐藏字段必须等于同名 cookie | `lua/login.lua` |
| 写操作同源栅栏 | 带 `Origin` 且 ≠ `scheme://Host` 的 `POST/PUT/PATCH/DELETE` → 403；安全方法放行；无 `Origin` 放行 | `lua/dshmu.lua:origin_ok()`，`me.lua` / `admin.lua` 入口 |
| 上游 DSH | trust fence（Host 回环/受信 + Origin==Host）+ 每实例独有 HMAC cookie，由网关代持 | DSH 自身 + `auth.lua` |
| 运维 API | 仅回环 **且** 必须带共享令牌（`?t=` 或 `X-DSH-MU-Admin`） | `lua/api.lua` |

`SameSite=Lax` 挡住绝大多数跨站写请求，同源栅栏是第二道（覆盖不支持 SameSite 的老浏览器与将来新增的
写接口）；两者都不影响 CLI/脚本，因为那些请求不带 `Origin`。
