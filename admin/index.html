实例

每个实例是一个受管 jail：独立 rootfs、独立端口、独立 cgroup。限额与出网策略改完立即生效，端口与挂载要重启才生效。

状态和实时必须分开看 状态读的是 openrc 服务单元，实时是每行一次 TCP connect（300ms 超时）。服务单元 running 但端口不接的情况真实存在，合并成一列就会骗人。

模型接入

provider 配置文件只决定「怎么连上游」。导入不建套餐、也不静默覆盖同名；套餐和默认模型在「模型套餐」里。写操作之后要 sync 并重启受影响实例。

三种入口，一条校验线 从模板库挑、贴 JSON、或从 DSH 目录勾选（含模型目录）。三条路都先按规范校验再落盘；导入只写 provider 配置文件，不建套餐，也不静默覆盖同名 provider —— 覆盖前会先问。 要一次装完可以直接 。

模型套餐

套餐 = provider + key + 名字，决定用户能选到哪些模型；默认模型链决定新会话从哪个套餐开始。provider 本身在「模型接入」里导入。

范围建时定，之后不能改 团队 = 所有用户可见；个人 = 只有 owner 自己可见（用户在面板里自建）。「隐藏」的套餐用户看不到，但平台仍然可以用它做搜索；plan_default 是内置保底，可停用、不可删。

默认模型（按优先级）

新会话的起始模型：按顺序取第一条该用户能看到的套餐 + 模型。用户在会话里换过模型，本会话以他的选择为准。

web_search 将使用：d13deepseek（顺序最靠前、能跑 DeepSeek 搜索的那个）

扩展管理

扩展是一个 apk 包（dsh-mu-*-ext）：自带 rootfs，在受管 jail 里跑自己的服务，并把自己那份 dsh 插件交给平台分发。安装 / 升级 / 卸载都走 apk，这里只看状态、起停、打开配置页。有托管页面的扩展会出现在左侧「扩展」组里，这里是它们的退路：没跑、要重启、要看日志。
